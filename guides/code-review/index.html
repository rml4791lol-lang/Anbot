使用场景

用 Bot 团队做一次只读代码审查

代码审查最怕两件事：Bot 读全仓库然后给你一堆风格意见，或者它根本没看 diff。Anbot 的做法是把审查范围、基线、输出格式先定死，再让「眼镜」预设只读这次改动。

一句话答案：把分支、基线、diff 范围和「只报新增且可触发的问题」写进任务；要求每条发现带文件、行号、复现路径和最小修法。Bot 不改代码，修不修由你决定。

适合谁

  • 需要快速过一遍 PR 的开发者
  • 想让审查结果可追溯的团队
  • 已经把 Claude Code、Codex 等本地 Agent 接进 Anbot 的人

怎么做

  1. 在仓库里切到待审分支，确认基线 commit；把 git diff <base>...HEAD 保存成文件，或直接让 Bot 在工作区读取。
  2. 新建审查 Bot，选择「眼镜」预设；指令里限定：只读本次 diff、不读全仓库、不评论风格、不猜测未出现的代码。
  3. 要求输出按严重程度排序：文件、行号、触发条件、影响、最小修法；没有证据的写成「待验证」，不要写成结论。
  4. 你逐条确认；需要修的地方再开一个修复任务，让另一个 Bot 在独立 worktree 里改，审查 Bot 不复用。

验收标准

  • 每条发现都能对应 diff 中的文件与行
  • 有复现步骤或明确的触发路径
  • 没有把历史问题算到这次改动上
  • 审查 Bot 没有直接改代码

边界与限制

  • 不能替代测试、类型检查和安全审计
  • 跨仓库、生成代码、复杂并发问题需要人补上下文
  • 本地 Agent 的审查能力取决于它自己的模型和工具

常见问题

Anbot 会自己改代码吗？

这个流程不会。审查 Bot 只读；需要修复时另开任务，并让它在独立工作区改。

能审整个仓库吗？

可以，但不建议。全仓库审查噪音大、成本高；先限定本次 diff，再按需扩大范围。
