Anbot Issue 分诊：关闭必须留证据

Issue 分诊不是把标签乱贴一遍。Anbot 的「Issue 分诊」技能先取一次仓库快照，只读地给出类型、优先级和领域标签；关闭或判定重复时，必须带证据。

本页是 30 篇指南中的 1 篇，基于 Anbot 0.0.1；下面给出 4 个步骤、4 条验收标准、3 个限制。

一句话答案：连接 GitHub 后，让分诊 Bot 读一次 Issue 和现有标签；每条给一个类型、一个优先级、一个领域，结论和证据一起写回；关闭前由人确认。

适合谁

  • Issue 多、标签乱的维护者
  • 想把分诊标准固定的团队
  • 需要每个关闭都有据可查的项目

怎么做

  1. 在 Anbot 里连接 GitHub（OAuth 或 MCP），只给需要的仓库读权限；先不要给写权限。
  2. 让 Bot 取一次 Issue 列表和现有标签快照；把分诊规则写进指令：类型、优先级、领域各一个。
  3. 要求每条结论附 Issue 链接和关键句；疑似重复要给出被重复 Issue 的编号；无法判断的标「待人工」。
  4. 人工确认后，再让 Bot 写标签或评论；关闭动作单独确认，不自动关闭。

验收标准

  • 每个 Issue 有类型、优先级、领域各一个标签
  • 关闭/重复结论有链接或引用证据
  • 没有改代码、没有自动合并 PR
  • 不确定的 Issue 留在待人工队列

边界与限制

  • 依赖仓库权限和标签体系；规则要先定
  • Bot 不能替代维护者的产品判断
  • 写操作要单独授权，避免误关

常见问题

Bot 会自动关闭 Issue 吗？

不会。这个流程只做分诊和写证据；关闭由人确认。

能同时分诊多个仓库吗？

可以，但建议按仓库分别设权限和规则，避免标签体系混在一起。
