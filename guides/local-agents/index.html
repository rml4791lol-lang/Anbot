Anbot 本地 Agent：把 Claude Code / Codex 接成团队 Bot

你机器上可能已经装了 Claude Code、Codex CLI、Cursor CLI、Gemini CLI 或其他编码 Agent。Anbot 可以把它们直接接成一个 Bot：它们用自己的登录、套餐、模型、工具和上下文，同时加入私聊、群聊、交接和记忆。

本页是 30 篇指南中的 1 篇，基于 Anbot 0.0.1；下面给出 4 个步骤、4 条验收标准、3 个限制。

一句话答案：在 Models / Local agents 里选择已安装并登录的 CLI，给它工作文件夹和权限；它仍然是那个 CLI 在跑，Anbot 负责团队协作、任务板和接管。

适合谁

  • 已经在用 Claude Code、Codex 等 CLI 的开发者
  • 想让多个编码 Agent 在一个群里协作的人
  • 需要保留 CLI 自己的套餐和登录状态的人

怎么做

  1. 先在终端安装并登录你要用的 CLI；确认它能独立跑通一个最小任务。
  2. 在 Anbot 的模型/本地 Agent 设置里选择它，指定工作文件夹和权限预设；需要时给它单独的 worktree。
  3. 把它拉进群聊，和 Main Bot、审阅 Bot 一起派活；说明它负责哪一段、交付什么文件、谁来验收。
  4. 用运行时探针确认「已安装、已登录」；需要你接手时用接管，交回时确认还是同一个 Session 和文件夹。

验收标准

  • 运行时探针显示 CLI 已安装并登录
  • 任务在独立工作区或 worktree 里，没覆盖主分支
  • 交接有明确产物和验收人
  • 没有把 Anbot 的连接器能力误当成 CLI 自带能力

边界与限制

  • 本地 Agent 用的是 CLI 自己的工具和上下文，Anbot 的共享连接器不会自动传进去
  • 在模型和本地 Agent 之间切换会开启新的对话分段
  • 只拒绝 MCP 的 CLI 无法使用团队工具；Cursor CLI 会保存它自己的全局默认模型

常见问题

本地 Agent 的 token 算在 Anbot 里吗？

不算。它使用 CLI 自己的登录、套餐和计费；Anbot 不代收这部分费用。

能同时接多个 CLI 吗？

可以。每个 Bot 可以选择不同的 CLI 或模型；团队协作通过群聊和交接完成。
