Anbot 安全吗？本地优先与审批边界

Anbot 的安全设计是「减少默认权限、把破坏性动作摆到台面上」：数据本地、危险命令审批、检查点、接管和运行时探针。它不是安全保证，也不能替代你的系统权限管理。

一句话答案：把权限给到最小、危险操作默认审批、关键任务先检查点、用独立工作区；不要把不可逆操作交给无人值守的 Bot。

适合谁

  • 要把 Bot 放进真实工作区的团队
  • 关心误删/误发布的负责人
  • 需要给安全评审解释的人

怎么做

  1. 按 Bot 给最小权限：只读、指定文件夹、指定工具；不要默认全盘/全部连接器。
  2. 把删除、推送、发布、改配置、外发邮件设为审批；高风险操作前强制检查点。
  3. 用独立 worktree/副本跑实验；接管时确认执行者已停，交回时确认 Session/文件夹。
  4. 用运行时探针核对加载的 MCP/技能/权限；对不上就停下来，不要假设。

验收标准

  • 每个 Bot 的权限可解释
  • 破坏性操作有人确认
  • 关键任务有检查点
  • 本地 Agent 的登录/权限单独管理

边界与限制

  • 不是沙箱/杀毒软件，不能保证恶意代码无害
  • 模型可能犯错，审批仍要人判断
  • 第三方 MCP/CLI 有自己的安全边界

常见问题

能完全无人值守吗？

不建议对不可逆操作无人值守；可以自动跑只读/可恢复的任务。

数据加密吗？

凭据放在 Secrets，具体保护方式取决于你的系统与配置；整体安全还取决于设备、权限和备份，不能一概而论。
