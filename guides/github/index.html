让 Anbot 接入 GitHub：Issue、PR 和 Actions 日志

接入 GitHub 后，Bot 可以在一次任务里读 Issue、看 PR diff、查 Actions 失败日志，再把结论写回评论。重点是权限要小、写操作要确认。

一句话答案：用 GitHub 连接器或 MCP 授权目标仓库；先只读，确认 Bot 能定位仓库/分支/PR；需要写评论或标签时再单独开权限。

适合谁

  • 要让 Bot 参与 PR 审查、Issue 分诊的团队
  • 需要把 CI 日志拉进上下文的开发者
  • 想限制 Bot 仓库权限的维护者

怎么做

  1. 在连接器里选 GitHub，授权目标仓库；优先用只读或最小 scope，不要一次给所有仓库。
  2. 让 Bot 先做一次只读任务：列出打开的 PR、最近失败的 Actions、相关 Issue；核对仓库和分支对不对。
  3. 需要写评论/标签时，明确允许的动作和范围；推送、合并、删除仍由人确认。
  4. 把常用查询写成固定指令，减少每次重新描述；敏感仓库单独隔离。

验收标准

  • Bot 能准确找到目标仓库、分支和 PR
  • 只读任务没有产生写操作
  • 写操作有明确范围和人工确认
  • CI 日志结论能回到具体 job/step

边界与限制

  • GitHub 权限和仓库规则仍然生效
  • 大仓库的 diff/日志可能超出上下文，需要分片
  • Bot 不能替代 CI 和安全扫描

常见问题

能给 Bot 仓库管理员权限吗？

不建议。按任务给最小权限，写操作单独确认。

支持 GitHub Enterprise 吗？

取决于连接器和 MCP 配置；先确认你的实例支持 OAuth 或 token 方式。
