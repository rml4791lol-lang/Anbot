让 Anbot 接入 MCP：把外部工具变成 Bot 能力

MCP 是把外部工具接进 Agent 的通用方式。Anbot 支持远程 MCP（OAuth 或 headers/key），也支持把 MCP 作为团队能力，按 Bot 设为 Always、Catalog 或 Off。

本页是 30 篇指南中的 1 篇，基于 Anbot 0.0.1；下面给出 4 个步骤、4 条验收标准、3 个限制。

一句话答案：先接一个只读 MCP，确认工具列表和权限；再把能力分配给需要的 Bot，默认按需加载；运行时探针确认加载了什么。

适合谁

  • 要把内部系统接进 Bot 的团队
  • 需要控制每个 Bot 能用哪些工具的人
  • 已经在用 MCP 的开发者

怎么做

  1. 在连接器里添加远程 MCP，填 OAuth 或 headers/key；先只接一个，确认能列出工具。
  2. 给 MCP 设置团队能力：Always 每轮加载、Catalog 按需加载、Off 关闭；不要把所有工具默认 Always。
  3. 为不同 Bot 分配不同能力；高风险工具只给特定 Bot，并保留审批。
  4. 用运行时探针检查当前 Session 加载了哪些 MCP、权限是什么；对不上就标「未验证」。

验收标准

  • Bot 只能看到分配给它的 MCP 工具
  • 高风险工具没有默认全开
  • 运行时能显示实际加载状态
  • MCP 凭据在 Secrets 中，不在指令里

边界与限制

  • MCP 服务器的质量和权限由提供方决定
  • 工具太多会占用上下文，按需加载更稳
  • 远程 MCP 需要网络和 OAuth 配置

常见问题

MCP 和插件有什么区别？

MCP 接的是外部工具服务；插件是装进 Anbot 的界面/运行时扩展。两者可以同时用。

能接本地 MCP 吗？

可以，通过本地 API/MCP 网关；具体命令和端口见文档。
