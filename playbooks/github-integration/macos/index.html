Anbot · 把 GitHub 接进 Bot 团队｜macOS版

接 GitHub 的第一原则是最小权限；先只读，再草稿，最后才谈写操作。 macOS 上先确认文件和权限；不要假设云端一定有副本。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先接一个仓库做只读，再让 Bot 生成 Issue/PR 草稿，合并和发布保留人工审批。 在macOS下，先先确认工作区路径、磁盘权限和 Apple 芯片/Intel 包，再按验收表逐项确认。

适合谁

  • 要让 Bot 处理 Issue/PR 的团队
  • 担心 Agent 改坏仓库的人
  • 需要把研发流程自动化的组织
  • 在 Mac 上运行的团队

怎么做

  1. 用最小权限接一个仓库，先只读 Issue、PR 和代码。
  2. 让 Bot 生成分诊、审查或发布草稿；写操作只写评论/草稿。
  3. 设审批点：合并、发布、改权限必须由人确认。
  4. 安装包按芯片选；首次运行按发布页说明放行。
  5. 文件操作只用本地路径；导出前检查换行和编码。

验收标准

  • Bot 只能访问授权仓库
  • 写操作有审批记录
  • 草稿能回到具体 Issue/PR
  • 没有直接推主分支
  • 安装包与芯片匹配，任务能在本机复跑

边界与限制

  • GitHub API 限流会影响批量任务
  • 私有仓库权限要单独配置
  • 不能替代代码所有者审查
  • 部分 Windows 专属工具/Office 能力可能不同

常见问题

能自动合并 PR 吗？

不建议；合并和发布保留人工确认。

能接多个组织吗？

可以，但每个组织单独授权。

Apple 芯片和 Intel 用同一个包吗？

不；发布页有 arm64 和 x64 两个包。
