Anbot · 把 Anbot 的输出接进现有系统｜代运营/客户交付版

集成的关键是契约；先定 JSON schema，再让 Bot 产出。 客户交付最怕串数据和串口径；先隔离客户，再复用模板。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定输出 schema 和校验，再让 Bot 写文件，最后由现有服务校验导入。 在代运营/客户交付下，先按客户建独立工作区和验收清单，再按验收表逐项确认。

适合谁

  • 要把结果进系统的开发者
  • 做自动化交付的团队
  • 需要稳定接口的人
  • 服务多个客户的代理/外包团队

怎么做

  1. 定义 JSON schema、必填字段、枚举和错误格式。
  2. 让 Bot 输出到 staging 文件，不直连生产库。
  3. 用现有服务做 schema 校验、幂等和导入；失败回到 staging。
  4. 每个客户单独目录、单独凭据、单独知识库，不共用上下文。
  5. 交付前用同一套验收复核；客户确认前不发布。

验收标准

  • schema 有版本
  • 输出可校验
  • 导入幂等
  • 失败不污染生产
  • 客户数据不跨项目混用，交付有客户确认记录

边界与限制

  • Anbot 不是 API 网关
  • 模型输出可能不稳定
  • 生产凭据不能给 Bot
  • 多客户并行会增加上下文和权限复杂度

常见问题

能让 Bot 直接写数据库吗？

不建议；走 staging + 校验。

输出格式会变吗？

用 schema 版本控制。

能复用同一个 Bot 吗？

可以复用能力模板，但客户数据和凭据必须隔离。
