Anbot · 把 Anbot 的输出接进现有系统｜Linear 优先版

集成的关键是契约；先定 JSON schema，再让 Bot 产出。 Linear 优先时状态只写一处；Bot 只做草稿/评论。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定输出 schema 和校验，再让 Bot 写文件，最后由现有服务校验导入。 在Linear 优先下，先先接一个项目只读，再生成分诊/验收草稿，再按验收表逐项确认。

适合谁

  • 要把结果进系统的开发者
  • 做自动化交付的团队
  • 需要稳定接口的人
  • 以 Linear 为任务真源的团队

怎么做

  1. 定义 JSON schema、必填字段、枚举和错误格式。
  2. 让 Bot 输出到 staging 文件，不直连生产库。
  3. 用现有服务做 schema 校验、幂等和导入；失败回到 staging。
  4. Issue 状态以 Linear 为准；外部表只读。
  5. 状态变更走审批；冲突回 Linear 处理。

验收标准

  • schema 有版本
  • 输出可校验
  • 导入幂等
  • 失败不污染生产
  • 没有双写，状态变更可追溯

边界与限制

  • Anbot 不是 API 网关
  • 模型输出可能不稳定
  • 生产凭据不能给 Bot
  • 工作流状态因团队而异，不能硬编码

常见问题

能让 Bot 直接写数据库吗？

不建议；走 staging + 校验。

输出格式会变吗？

用 schema 版本控制。

能自动关闭 Issue 吗？

先写关闭建议，由人确认。
