Anbot · 把 Anbot 的输出接进现有系统｜运营/行政版

集成的关键是契约；先定 JSON schema，再让 Bot 产出。 运营任务要固定输入模板和输出目录，减少口头变体。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定输出 schema 和校验，再让 Bot 写文件，最后由现有服务校验导入。 在运营/行政下，先先固定输入模板、命名和归档目录，再按验收表逐项确认。

适合谁

  • 要把结果进系统的开发者
  • 做自动化交付的团队
  • 需要稳定接口的人
  • 运营、行政、财务等流程岗位

怎么做

  1. 定义 JSON schema、必填字段、枚举和错误格式。
  2. 让 Bot 输出到 staging 文件，不直连生产库。
  3. 用现有服务做 schema 校验、幂等和导入；失败回到 staging。
  4. 每类任务做一个模板；字段不齐的先补，不要靠猜。
  5. 输出按日期/项目归档；每周抽查一次重复和漏项。

验收标准

  • schema 有版本
  • 输出可校验
  • 导入幂等
  • 失败不污染生产
  • 同类任务输出结构一致，能批量复核

边界与限制

  • Anbot 不是 API 网关
  • 模型输出可能不稳定
  • 生产凭据不能给 Bot
  • 例外流程多，模板不可能覆盖全部

常见问题

能让 Bot 直接写数据库吗？

不建议；走 staging + 校验。

输出格式会变吗？

用 schema 版本控制。

能处理临时需求吗？

可以，但先标为例外，不要污染标准模板。
