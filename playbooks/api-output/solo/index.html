Anbot · 把 Anbot 的输出接进现有系统｜一人公司版

集成的关键是契约；先定 JSON schema，再让 Bot 产出。 你既是老板也是执行者，最缺的是可复跑和可验收，而不是更多 Bot。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定输出 schema 和校验，再让 Bot 写文件，最后由现有服务校验导入。 在一人公司下，先先把 Bot 压到 1–2 个，选一条能独立验收的链路，再按验收表逐项确认。

适合谁

  • 要把结果进系统的开发者
  • 做自动化交付的团队
  • 需要稳定接口的人
  • 一个人负责从输入到交付的从业者

怎么做

  1. 定义 JSON schema、必填字段、枚举和错误格式。
  2. 让 Bot 输出到 staging 文件，不直连生产库。
  3. 用现有服务做 schema 校验、幂等和导入；失败回到 staging。
  4. 把输入、输出目录和验收清单写在同一个文件里，避免靠记忆。
  5. 每次只改一个变量；失败时回到上一个检查点，不要同时调模型和流程。

验收标准

  • schema 有版本
  • 输出可校验
  • 导入幂等
  • 失败不污染生产
  • 一个人能在 30 分钟内复跑并解释结果

边界与限制

  • Anbot 不是 API 网关
  • 模型输出可能不稳定
  • 生产凭据不能给 Bot
  • 没有第二个人交叉复核，事实性结论要额外抽检

常见问题

能让 Bot 直接写数据库吗？

不建议；走 staging + 校验。

输出格式会变吗？

用 schema 版本控制。

一个人需要几个 Bot？

先 1 个 Main Bot + 1 个专业 Bot，跑通再加；不要用 Bot 数量掩盖流程问题。
