Anbot · 把 Anbot 的输出接进现有系统｜纯本地数据版

集成的关键是契约；先定 JSON schema，再让 Bot 产出。 纯本地场景先确认模型和工具都不外传，再谈能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定输出 schema 和校验，再让 Bot 写文件，最后由现有服务校验导入。 在纯本地数据下，先先列数据流，关掉会外传内容的连接器，再按验收表逐项确认。

适合谁

  • 要把结果进系统的开发者
  • 做自动化交付的团队
  • 需要稳定接口的人
  • 数据不能出本机的团队

怎么做

  1. 定义 JSON schema、必填字段、枚举和错误格式。
  2. 让 Bot 输出到 staging 文件，不直连生产库。
  3. 用现有服务做 schema 校验、幂等和导入；失败回到 staging。
  4. 模型、检索、日志都留在本机；逐项确认没有外部请求。
  5. 敏感文件先脱敏；本地模型能力不足时明确降级范围。

验收标准

  • schema 有版本
  • 输出可校验
  • 导入幂等
  • 失败不污染生产
  • 数据流图显示没有外部传输，日志本地保存

边界与限制

  • Anbot 不是 API 网关
  • 模型输出可能不稳定
  • 生产凭据不能给 Bot
  • 本地模型能力和更新速度有限

常见问题

能让 Bot 直接写数据库吗？

不建议；走 staging + 校验。

输出格式会变吗？

用 schema 版本控制。

能完全离线吗？

取决于模型和工具；先确认哪些步骤需要联网。
