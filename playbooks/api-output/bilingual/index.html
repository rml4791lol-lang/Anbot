Anbot · 把 Anbot 的输出接进现有系统｜中英双语版

集成的关键是契约；先定 JSON schema，再让 Bot 产出。 双语交付从同一份事实表生成，不要先写中文再逐句硬翻。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定输出 schema 和校验，再让 Bot 写文件，最后由现有服务校验导入。 在中英双语下，先先做双语术语表和事实表，再分别成稿，再按验收表逐项确认。

适合谁

  • 要把结果进系统的开发者
  • 做自动化交付的团队
  • 需要稳定接口的人
  • 需要中英双版本交付的团队

怎么做

  1. 定义 JSON schema、必填字段、枚举和错误格式。
  2. 让 Bot 输出到 staging 文件，不直连生产库。
  3. 用现有服务做 schema 校验、幂等和导入；失败回到 staging。
  4. 数字、日期、链接只维护一份；两种语言都引用它。
  5. 两版逐段对照，标出意译和不确定处。

验收标准

  • schema 有版本
  • 输出可校验
  • 导入幂等
  • 失败不污染生产
  • 两版事实一致，术语一致，能逐段对照

边界与限制

  • Anbot 不是 API 网关
  • 模型输出可能不稳定
  • 生产凭据不能给 Bot
  • 双语维护成本高，更新要同步

常见问题

能让 Bot 直接写数据库吗？

不建议；走 staging + 校验。

输出格式会变吗？

用 schema 版本控制。

能只维护中文吗？

不建议；对外双语版本要同步更新。
