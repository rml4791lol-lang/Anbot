Anbot · 把 Anbot 的输出接进现有系统｜英文交付版

集成的关键是契约；先定 JSON schema，再让 Bot 产出。 英文交付要统一拼写、日期、货币和语气，避免直译中文长句。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定输出 schema 和校验，再让 Bot 写文件，最后由现有服务校验导入。 在英文交付下，先先定术语表、拼写体系和日期格式，再按验收表逐项确认。

适合谁

  • 要把结果进系统的开发者
  • 做自动化交付的团队
  • 需要稳定接口的人
  • 对外产物以英文为主的团队

怎么做

  1. 定义 JSON schema、必填字段、枚举和错误格式。
  2. 让 Bot 输出到 staging 文件，不直连生产库。
  3. 用现有服务做 schema 校验、幂等和导入；失败回到 staging。
  4. 用目标市场的拼写/日期/货币；全文一致。
  5. 长句拆短；不确定的表达标出来让母语者审。

验收标准

  • schema 有版本
  • 输出可校验
  • 导入幂等
  • 失败不污染生产
  • 拼写/日期/货币一致，母语者可读

边界与限制

  • Anbot 不是 API 网关
  • 模型输出可能不稳定
  • 生产凭据不能给 Bot
  • 非母语审校可能漏掉语气问题

常见问题

能让 Bot 直接写数据库吗？

不建议；走 staging + 校验。

输出格式会变吗？

用 schema 版本控制。

能保持品牌语气吗？

提供 2–3 个英文样例最有效。
