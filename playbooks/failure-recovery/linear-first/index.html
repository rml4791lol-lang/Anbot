Anbot · 从一次失败任务里恢复并复盘｜Linear 优先版

失败后最忌讳直接重跑；先保留现场，再判断哪一层坏了。 Linear 优先时状态只写一处；Bot 只做草稿/评论。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先停任务保现场，再按输入/工具/模型/权限分层定位，最后补防再重跑。 在Linear 优先下，先先接一个项目只读，再生成分诊/验收草稿，再按验收表逐项确认。

适合谁

  • 跑自动化失败的人
  • 需要写故障报告的人
  • 经常重复踩坑的团队
  • 以 Linear 为任务真源的团队

怎么做

  1. 停止任务，保留日志、输入、输出和版本。
  2. 按输入/工具/模型/权限/外部服务分层排查。
  3. 写失败原因和防再发措施；只重跑受影响的最小范围。
  4. Issue 状态以 Linear 为准；外部表只读。
  5. 状态变更走审批；冲突回 Linear 处理。

验收标准

  • 现场证据完整
  • 失败层有结论
  • 防再发有具体动作
  • 重跑范围最小
  • 没有双写，状态变更可追溯

边界与限制

  • 部分外部故障无法复现
  • 日志可能含敏感信息
  • 不能保证一次定位
  • 工作流状态因团队而异，不能硬编码

常见问题

能自动重跑吗？

先定位；盲目重跑会重复副作用。

需要写事故报告吗？

高风险/客户可见的失败建议写。

能自动关闭 Issue 吗？

先写关闭建议，由人确认。
