Anbot · 确认 Anbot 的开源边界｜Linux版

开源不等于所有东西都免费；代码、模型、服务和商标要分开看。 Linux 多用于构建和服务；先准备依赖，再谈桌面能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先看 LICENSE 和 NOTICE，再确认模型由服务商计费，最后区分商标/第三方组件。 在Linux下，先先确认 Node/依赖、权限和是否需要图形界面，再按验收表逐项确认。

适合谁

  • 要商用 Anbot 的团队
  • 需要给客户解释许可证的人
  • 准备二次开发的开发者
  • 在 Linux 服务器/桌面运行的团队

怎么做

  1. 读仓库 LICENSE/NOTICE，确认 Apache 2.0 义务。
  2. 列出模型服务商、第三方组件和商标，分别确认条款。
  3. 把「代码免费/模型计费/服务自理」写进采购/交付说明。
  4. 从源码构建，记录版本和依赖；不要混用系统 Node。
  5. 无图形界面的环境只跑能无头执行的任务，桌面能力另行确认。

验收标准

  • 许可证类型明确
  • 第三方组件有清单
  • 模型费用说明清楚
  • 没有把开源当成无条件
  • 构建可复现，任务在目标环境跑通

边界与限制

  • 许可证解释需法务确认
  • 第三方组件可能变更
  • 商标使用需授权
  • 官方没有 Linux 安装包，桌面能力不保证

常见问题

能商用吗？

Apache 2.0 通常允许，但仍需履行许可证义务；以法务为准。

模型也免费吗？

不；模型调用由你配置的服务商计费。

有 Linux 安装包吗？

当前发布页没有；需要从源码构建。
