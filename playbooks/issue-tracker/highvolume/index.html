Anbot · 把多个 Issue 来源合并成一张表｜高并发/批量版

多来源 Issue 最怕重复和状态冲突；先定真源和映射。 高批量先做清单、分批、限流和失败重试，不要一个 Bot 串行到底。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先统一字段和真源，再拉取去重，最后生成只读汇总表和冲突清单。 在高并发/批量下，先先做 5 个样本，测吞吐/失败率，再分批放量，再按验收表逐项确认。

适合谁

  • 同时用 GitHub/Linear 的团队
  • 要跨项目看问题的人
  • 需要给管理层汇总的人
  • 要跑几百到几千个任务的团队

怎么做

  1. 定义统一字段：标题、状态、优先级、负责人、来源。
  2. 拉取各来源并去重；同一问题保留主链接和关联链接。
  3. 生成汇总表和冲突清单；状态变更回到各自真源处理。
  4. 按优先级/大小分批；每批有独立输出目录和失败清单。
  5. 设并发上限和退避；失败只重跑失败项。

验收标准

  • 字段映射一致
  • 重复项有主记录
  • 来源链接可追溯
  • 没有双写状态
  • 样本通过、吞吐可测、失败可重跑、成本可控

边界与限制

  • 各系统状态语义不同
  • API 限流影响同步
  • 权限要分别配置
  • 模型/API 限流和磁盘/内存会限制规模

常见问题

能统一改状态吗？

不建议；以各系统真源为准。

能做看板吗？

可以生成只读看板。

能一次跑 3000 个吗？

先分批；直接全量容易在中途限流。
