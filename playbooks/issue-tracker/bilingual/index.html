Anbot · 把多个 Issue 来源合并成一张表｜中英双语版

多来源 Issue 最怕重复和状态冲突；先定真源和映射。 双语交付从同一份事实表生成，不要先写中文再逐句硬翻。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先统一字段和真源，再拉取去重，最后生成只读汇总表和冲突清单。 在中英双语下，先先做双语术语表和事实表，再分别成稿，再按验收表逐项确认。

适合谁

  • 同时用 GitHub/Linear 的团队
  • 要跨项目看问题的人
  • 需要给管理层汇总的人
  • 需要中英双版本交付的团队

怎么做

  1. 定义统一字段：标题、状态、优先级、负责人、来源。
  2. 拉取各来源并去重；同一问题保留主链接和关联链接。
  3. 生成汇总表和冲突清单；状态变更回到各自真源处理。
  4. 数字、日期、链接只维护一份；两种语言都引用它。
  5. 两版逐段对照，标出意译和不确定处。

验收标准

  • 字段映射一致
  • 重复项有主记录
  • 来源链接可追溯
  • 没有双写状态
  • 两版事实一致，术语一致，能逐段对照

边界与限制

  • 各系统状态语义不同
  • API 限流影响同步
  • 权限要分别配置
  • 双语维护成本高，更新要同步

常见问题

能统一改状态吗？

不建议；以各系统真源为准。

能做看板吗？

可以生成只读看板。

能只维护中文吗？

不建议；对外双语版本要同步更新。
