Anbot · 让多个 Bot 并行做任务｜Notion 优先版

并行不是多开几个 Bot；要先保证子任务真的独立。 Notion 优先时先定一个数据库做真源，页面只做视图。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先拆独立子任务和共享事实，再并行执行，最后合并验收和冲突。 在Notion 优先下，先先选一个数据库只读，再让 Bot 写草稿页，再按验收表逐项确认。

适合谁

  • 要加速交付的团队
  • 任务可拆成多角色的项目
  • 需要多 Agent 协作的人
  • 以 Notion 为知识/项目真源的团队

怎么做

  1. 拆子任务，标出依赖和共享事实；不独立的不要并行。
  2. 给每个 Bot 明确交付、边界和写入目录。
  3. 合并产物，检查冲突和重复；统一验收后再交付。
  4. 字段和数据库结构先定；不要为每个 Bot 建新库。
  5. 发布/归档由人确认；Bot 不改权限。

验收标准

  • 子任务独立可验收
  • 共享事实一致
  • 写入不冲突
  • 合并后有总验收
  • 单一真源清楚，草稿有来源，没有重复数据库

边界与限制

  • 并行会增加协调成本
  • 模型/API 限流
  • 共享上下文可能不一致
  • Notion API 速率/结构变化会影响同步

常见问题

Bot 越多越快吗？

不一定；协调和返工会吃掉收益。

怎么避免冲突？

分目录/分文件，合并前先 diff。

能整理整个 workspace 吗？

先从一个数据库开始，避免污染。
