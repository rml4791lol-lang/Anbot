Anbot · 用 MCP 接一个外部工具｜云模型版

MCP 的风险在权限扩散；先接一个只读工具，再谈写操作。 云模型先分开「文件在哪」和「内容发给谁」，敏感数据先脱敏。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先接一个只读 MCP，确认工具列表，再按 Bot 分配权限，高风险工具保留审批。 在云模型下，先先确认服务商条款、数据保留和可脱敏字段，再按验收表逐项确认。

适合谁

  • 要把内部系统接进 Bot 的团队
  • 用 MCP 的开发者
  • 需要控制工具权限的人
  • 使用云模型服务商的团队

怎么做

  1. 添加一个远程/本地 MCP，先只读并列出工具。
  2. 把工具设为按需加载，按 Bot 分配；高风险工具默认关闭。
  3. 用运行时探针确认实际加载了哪些工具和权限。
  4. 只发必要字段；能本地预处理就不要整文件上传。
  5. 记录模型服务商、区域和保留政策；敏感任务保留人工复核。

验收标准

  • 工具清单可见
  • 权限按 Bot 分配
  • 高风险工具没有默认全开
  • 凭据不在指令里
  • 发送字段最小化，服务商和保留政策有记录

边界与限制

  • MCP 服务器质量由提供方决定
  • 工具太多会占上下文
  • 远程 MCP 需要 OAuth/网络
  • 服务商条款和价格会变，跨境传输要单独确认

常见问题

MCP 和插件有什么区别？

MCP 接外部工具服务；插件是装进运行时的扩展。

能接本地 MCP 吗？

可以，通过本地网关；具体端口看文档。

云模型会保存数据吗？

看服务商条款；不要把不确定当成不会保存。
