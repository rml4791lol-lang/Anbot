Anbot · 把 Linear 接成任务真源｜高并发/批量版

任务系统最怕双写；先定 Linear 为真源，再让 Bot 做辅助。 高批量先做清单、分批、限流和失败重试，不要一个 Bot 串行到底。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先只读项目和 Issue，再让 Bot 生成草稿/评论，状态变更走审批。 在高并发/批量下，先先做 5 个样本，测吞吐/失败率，再分批放量，再按验收表逐项确认。

适合谁

  • 用 Linear 管研发的团队
  • 要让 Bot 分诊 Issue 的人
  • 经常双写任务系统的组织
  • 要跑几百到几千个任务的团队

怎么做

  1. 接一个团队/项目，只读 Issue、状态和标签。
  2. 让 Bot 生成分诊草稿、验收清单或评论；不要直接改状态。
  3. 设状态变更审批和冲突处理；以 Linear 为唯一真源。
  4. 按优先级/大小分批；每批有独立输出目录和失败清单。
  5. 设并发上限和退避；失败只重跑失败项。

验收标准

  • 没有双写
  • 状态变更可追溯
  • 草稿能回到 Issue
  • 冲突有处理规则
  • 样本通过、吞吐可测、失败可重跑、成本可控

边界与限制

  • Linear API 权限有限
  • 工作流状态因团队而异
  • 不能替代项目负责人判断
  • 模型/API 限流和磁盘/内存会限制规模

常见问题

能自动关闭 Issue 吗？

不建议；先写关闭建议。

能和 GitHub 同时用吗？

可以，但先定哪个是真源。

能一次跑 3000 个吗？

先分批；直接全量容易在中途限流。
