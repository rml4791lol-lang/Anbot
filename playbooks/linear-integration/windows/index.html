Anbot · 把 Linear 接成任务真源｜Windows版

任务系统最怕双写；先定 Linear 为真源，再让 Bot 做辅助。 Windows 上先测路径、换行和 Office 兼容，再放量。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先只读项目和 Issue，再让 Bot 生成草稿/评论，状态变更走审批。 在Windows下，先先确认安装包、路径分隔符和 Office 版本，再按验收表逐项确认。

适合谁

  • 用 Linear 管研发的团队
  • 要让 Bot 分诊 Issue 的人
  • 经常双写任务系统的组织
  • 在 Windows 上运行的团队

怎么做

  1. 接一个团队/项目，只读 Issue、状态和标签。
  2. 让 Bot 生成分诊草稿、验收清单或评论；不要直接改状态。
  3. 设状态变更审批和冲突处理；以 Linear 为唯一真源。
  4. 用 Windows 安装包；路径尽量用绝对路径并加引号。
  5. 批量脚本先在样本目录跑；确认编码和换行一致。

验收标准

  • 没有双写
  • 状态变更可追溯
  • 草稿能回到 Issue
  • 冲突有处理规则
  • 路径/编码/Office 兼容通过样本测试

边界与限制

  • Linear API 权限有限
  • 工作流状态因团队而异
  • 不能替代项目负责人判断
  • 不同 Windows 版本的权限和字体有差异

常见问题

能自动关闭 Issue 吗？

不建议；先写关闭建议。

能和 GitHub 同时用吗？

可以，但先定哪个是真源。

Windows 10 能用吗？

发布页写明 Windows 10/11 64 位；以实际安装结果为准。
