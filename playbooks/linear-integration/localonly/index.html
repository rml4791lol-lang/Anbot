Anbot · 把 Linear 接成任务真源｜纯本地数据版

任务系统最怕双写；先定 Linear 为真源，再让 Bot 做辅助。 纯本地场景先确认模型和工具都不外传，再谈能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先只读项目和 Issue，再让 Bot 生成草稿/评论，状态变更走审批。 在纯本地数据下，先先列数据流，关掉会外传内容的连接器，再按验收表逐项确认。

适合谁

  • 用 Linear 管研发的团队
  • 要让 Bot 分诊 Issue 的人
  • 经常双写任务系统的组织
  • 数据不能出本机的团队

怎么做

  1. 接一个团队/项目，只读 Issue、状态和标签。
  2. 让 Bot 生成分诊草稿、验收清单或评论；不要直接改状态。
  3. 设状态变更审批和冲突处理；以 Linear 为唯一真源。
  4. 模型、检索、日志都留在本机；逐项确认没有外部请求。
  5. 敏感文件先脱敏；本地模型能力不足时明确降级范围。

验收标准

  • 没有双写
  • 状态变更可追溯
  • 草稿能回到 Issue
  • 冲突有处理规则
  • 数据流图显示没有外部传输，日志本地保存

边界与限制

  • Linear API 权限有限
  • 工作流状态因团队而异
  • 不能替代项目负责人判断
  • 本地模型能力和更新速度有限

常见问题

能自动关闭 Issue 吗？

不建议；先写关闭建议。

能和 GitHub 同时用吗？

可以，但先定哪个是真源。

能完全离线吗？

取决于模型和工具；先确认哪些步骤需要联网。
