Anbot · 把 Linear 接成任务真源｜免费额度版

任务系统最怕双写；先定 Linear 为真源，再让 Bot 做辅助。 免费额度先算限流和失败重试，不要把重任务押在免费层。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先只读项目和 Issue，再让 Bot 生成草稿/评论，状态变更走审批。 在免费额度下，先先测额度、限流和失败率，再定任务上限，再按验收表逐项确认。

适合谁

  • 用 Linear 管研发的团队
  • 要让 Bot 分诊 Issue 的人
  • 经常双写任务系统的组织
  • 依赖免费额度/试用版的团队

怎么做

  1. 接一个团队/项目，只读 Issue、状态和标签。
  2. 让 Bot 生成分诊草稿、验收清单或评论；不要直接改状态。
  3. 设状态变更审批和冲突处理；以 Linear 为唯一真源。
  4. 把重任务拆成小步；每步可缓存/重试。
  5. 设额度告警和降级方案；超额时暂停而不是盲目重试。

验收标准

  • 没有双写
  • 状态变更可追溯
  • 草稿能回到 Issue
  • 冲突有处理规则
  • 额度/限流有实测数据，失败有降级

边界与限制

  • Linear API 权限有限
  • 工作流状态因团队而异
  • 不能替代项目负责人判断
  • 免费层通常有速率/功能限制，不能保证稳定

常见问题

能自动关闭 Issue 吗？

不建议；先写关闭建议。

能和 GitHub 同时用吗？

可以，但先定哪个是真源。

不建议；先测单页成本，再分批。
