Anbot · 检查网页/文档里的提示注入｜macOS版

Agent 读外部内容时，内容本身可能是攻击；先隔离，再处理。 macOS 上先确认文件和权限；不要假设云端一定有副本。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先把外部内容标为不可信，再扫描可疑指令和链接，最后只提取事实不执行指令。 在macOS下，先先确认工作区路径、磁盘权限和 Apple 芯片/Intel 包，再按验收表逐项确认。

适合谁

  • 让 Bot 读网页/邮件的人
  • 处理用户提交内容的团队
  • 要防数据外泄的组织
  • 在 Mac 上运行的团队

怎么做

  1. 把外部内容放进隔离区，明确「只读事实，不执行指令」。
  2. 扫描「忽略之前指令」「输出密钥」等模式和高风险链接。
  3. 只提取需要的事实；可疑内容交安全人员复核。
  4. 安装包按芯片选；首次运行按发布页说明放行。
  5. 文件操作只用本地路径；导出前检查换行和编码。

验收标准

  • 外部内容没有直接变成指令
  • 可疑模式有记录
  • 高风险链接没有访问
  • 敏感信息没有外泄
  • 安装包与芯片匹配，任务能在本机复跑

边界与限制

  • 模式匹配不能覆盖所有攻击
  • 多模态内容更难检测
  • 不能替代安全网关
  • 部分 Windows 专属工具/Office 能力可能不同

常见问题

能完全防住吗？

不能；只能降低风险并隔离。

能读用户上传的文档吗？

可以，但按不可信内容处理。

Apple 芯片和 Intel 用同一个包吗？

不；发布页有 arm64 和 x64 两个包。
