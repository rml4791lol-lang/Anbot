Anbot · 做一次代码安全检查｜英文交付版

安全检查要先定范围；没有范围的「全面扫描」只会给一堆噪声。 英文交付要统一拼写、日期、货币和语气，避免直译中文长句。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先按五类风险列检查项，再让 Bot 找证据，最后人工分级和修复。 在英文交付下，先先定术语表、拼写体系和日期格式，再按验收表逐项确认。

适合谁

  • 要过安全评审的团队
  • 处理用户数据的开发
  • 需要给客户安全说明的人
  • 对外产物以英文为主的团队

怎么做

  1. 确定代码范围、入口、信任边界和已知风险。
  2. 按注入/鉴权/密钥/依赖/日志五类检查，给文件行号和证据。
  3. 人工分级；修复另开任务，不在审查中直接改生产代码。
  4. 用目标市场的拼写/日期/货币；全文一致。
  5. 长句拆短；不确定的表达标出来让母语者审。

验收标准

  • 每项风险有位置和证据
  • 区分确定/可能/误报
  • 密钥没有出现在输出
  • 修复建议可执行
  • 拼写/日期/货币一致，母语者可读

边界与限制

  • 不能替代专业渗透测试
  • 动态风险需要运行环境
  • 依赖漏洞库可能滞后
  • 非母语审校可能漏掉语气问题

常见问题

能自动修漏洞吗？

可以生成修复草稿；生产改动要人审。

能扫二进制吗？

能力有限；建议用专业工具。

能保持品牌语气吗？

提供 2–3 个英文样例最有效。
