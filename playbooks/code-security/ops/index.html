Anbot · 做一次代码安全检查｜运营/行政版

安全检查要先定范围；没有范围的「全面扫描」只会给一堆噪声。 运营任务要固定输入模板和输出目录，减少口头变体。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先按五类风险列检查项，再让 Bot 找证据，最后人工分级和修复。 在运营/行政下，先先固定输入模板、命名和归档目录，再按验收表逐项确认。

适合谁

  • 要过安全评审的团队
  • 处理用户数据的开发
  • 需要给客户安全说明的人
  • 运营、行政、财务等流程岗位

怎么做

  1. 确定代码范围、入口、信任边界和已知风险。
  2. 按注入/鉴权/密钥/依赖/日志五类检查，给文件行号和证据。
  3. 人工分级；修复另开任务，不在审查中直接改生产代码。
  4. 每类任务做一个模板；字段不齐的先补，不要靠猜。
  5. 输出按日期/项目归档；每周抽查一次重复和漏项。

验收标准

  • 每项风险有位置和证据
  • 区分确定/可能/误报
  • 密钥没有出现在输出
  • 修复建议可执行
  • 同类任务输出结构一致，能批量复核

边界与限制

  • 不能替代专业渗透测试
  • 动态风险需要运行环境
  • 依赖漏洞库可能滞后
  • 例外流程多，模板不可能覆盖全部

常见问题

能自动修漏洞吗？

可以生成修复草稿；生产改动要人审。

能扫二进制吗？

能力有限；建议用专业工具。

能处理临时需求吗？

可以，但先标为例外，不要污染标准模板。
