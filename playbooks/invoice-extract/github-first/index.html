Anbot · 从发票 PDF 提取结构化字段｜GitHub 优先版

发票提取的难点不是识别文字，而是字段对齐和金额校验。 GitHub 优先时先只读接入，写操作走草稿和审批。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定义字段和校验规则，再逐张提取，最后用总额/税额/明细做交叉校验。 在GitHub 优先下，先先接一个仓库只读，再让 Bot 写 Issue/PR 草稿，再按验收表逐项确认。

适合谁

  • 要录发票的人
  • 做报销/对账的人
  • 需要批量处理 PDF 的团队
  • 以 GitHub 为任务/代码真源的团队

怎么做

  1. 定义字段：发票号、日期、买卖方、金额、税额、明细。
  2. 逐张提取并保留页码/坐标；看不清的字段标「待人工」。
  3. 校验总额=明细合计、税额计算和重复发票；输出 CSV 与异常清单。
  4. Issue/PR 状态以 GitHub 为准；其他表只做视图。
  5. 合并、发布、改权限保留人工审批。

验收标准

  • 字段有空值处理规则
  • 金额校验能对上
  • 重复发票有标记
  • 原始 PDF 未被修改
  • 没有双写，草稿能回到具体 Issue/PR

边界与限制

  • 扫描质量差会影响识别
  • 不同票种模板差异大
  • 不能替代财务合规审核
  • API 限流和私有仓库权限要单独处理

常见问题

能开票吗？

不能；只做提取和校验。

能批量跑吗？

可以，但要分批并保留失败清单。

能自动合并吗？

不建议；合并和发布保留人工确认。
