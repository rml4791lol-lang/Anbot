Anbot · 根据改动生成测试计划｜MCP 优先版

测试计划最怕「全量回归」四个字；先按改动影响面缩小范围。 MCP 优先时先接只读工具，按 Bot 分配权限，高风险工具默认关闭。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先列行为变化和受影响模块，再给正常/边界/失败三类用例，最后标出无法自动化的部分。 在MCP 优先下，先先接一个只读 MCP，列出工具清单，再按验收表逐项确认。

适合谁

  • 要写 PR 测试说明的开发
  • 需要安排回归的 QA
  • 想让测试和验收对齐的负责人
  • 用 MCP 接内部工具的团队

怎么做

  1. 读 diff、接口定义和现有测试，列出行为变化。
  2. 按正常路径、边界条件、失败恢复生成用例，每条写预期结果。
  3. 标明哪些能自动跑、哪些要手工；把未覆盖风险写进限制。
  4. 工具按需加载，不要全部 Always。
  5. 运行时探针确认实际加载和权限。

验收标准

  • 每条用例对应一个行为变化
  • 边界和失败路径都有覆盖
  • 自动化/手工边界清楚
  • 测试数据不包含真实敏感信息
  • 工具清单可见，权限按 Bot 分配，高风险默认关闭

边界与限制

  • 看不到线上真实流量
  • 无法保证覆盖所有集成组合
  • 测试计划不等于测试执行
  • MCP 服务器质量和限流由提供方决定

常见问题

能直接跑测试吗？

可以执行仓库里的测试命令；结果要回到日志和退出码。

没有现成测试怎么办？

先补最小回归用例，不要假装全量覆盖。

能接本地 MCP 吗？

可以，通过本地网关；具体端口看文档。
