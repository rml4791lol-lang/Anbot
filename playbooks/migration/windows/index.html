Anbot · 从现有工具迁移到 Anbot｜Windows版

迁移不是把文件复制过来；要保留结构、权限和可回退。 Windows 上先测路径、换行和 Office 兼容，再放量。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先盘点并备份，再按资料/任务/自动化三阶段迁，最后验证和回退。 在Windows下，先先确认安装包、路径分隔符和 Office 版本，再按验收表逐项确认。

适合谁

  • 要从其他 Agent 迁移的人
  • 换工作流的管理者
  • 需要保留历史记录的组织
  • 在 Windows 上运行的团队

怎么做

  1. 盘点现有文件、任务、权限和自动化，做完整备份。
  2. 先迁只读资料，再迁任务，最后迁自动化；每阶段验收。
  3. 保留旧系统只读一段时间；写回退步骤。
  4. 用 Windows 安装包；路径尽量用绝对路径并加引号。
  5. 批量脚本先在样本目录跑；确认编码和换行一致。

验收标准

  • 原数据有备份
  • 分阶段验收
  • 权限映射清楚
  • 有回退路径
  • 路径/编码/Office 兼容通过样本测试

边界与限制

  • 格式/权限可能不兼容
  • 历史上下文难迁移
  • 迁移期双系统成本
  • 不同 Windows 版本的权限和字体有差异

常见问题

能一键迁移吗？

不假设；分阶段更安全。

旧数据要删吗？

验证后再按政策归档/删除。

Windows 10 能用吗？

发布页写明 Windows 10/11 64 位；以实际安装结果为准。
