Anbot · 判断一个任务要不要多 Agent｜MCP 优先版

多 Agent 只适合能拆、能验收、能交接的任务；否则是成本。 MCP 优先时先接只读工具，按 Bot 分配权限，高风险工具默认关闭。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先判断任务能否拆成独立子任务，再算协调成本，最后决定单 Agent 还是团队。 在MCP 优先下，先先接一个只读 MCP，列出工具清单，再按验收表逐项确认。

适合谁

  • 在选单/多 Agent 的人
  • 任务经常卡在交接的团队
  • 想上多 Agent 的管理者
  • 用 MCP 接内部工具的团队

怎么做

  1. 列任务步骤、角色、依赖和验收标准。
  2. 如果子任务不能独立验收，先用单 Agent。
  3. 能拆的先用 1 Main + 1 专业 Bot 试点，量协调成本。
  4. 工具按需加载，不要全部 Always。
  5. 运行时探针确认实际加载和权限。

验收标准

  • 拆分有验收
  • 协调成本可量化
  • 没有为多而多
  • 失败能回退单 Agent
  • 工具清单可见，权限按 Bot 分配，高风险默认关闭

边界与限制

  • 多 Agent 协调成本高
  • 模型调用更贵
  • 简单任务反而更慢
  • MCP 服务器质量和限流由提供方决定

常见问题

多 Agent 一定更强吗？

不一定；只在可拆分任务上有优势。

最少几个？

先 2 个，跑通再加。

能接本地 MCP 吗？

可以，通过本地网关；具体端口看文档。
