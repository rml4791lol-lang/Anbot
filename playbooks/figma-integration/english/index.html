Anbot · 把 Figma 接进设计交接｜英文交付版

设计交接不是发个链接；要把组件、状态、文案和边界写清。 英文交付要统一拼写、日期、货币和语气，避免直译中文长句。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先只读一个文件，提取组件和文案，再生成交接清单，改动由设计师确认。 在英文交付下，先先定术语表、拼写体系和日期格式，再按验收表逐项确认。

适合谁

  • 设计和开发交接的团队
  • 要从 Figma 提取文案的人
  • 需要减少设计走查的人
  • 对外产物以英文为主的团队

怎么做

  1. 接一个 Figma 文件，只读页面、组件和文本。
  2. 生成组件清单、状态、文案和待确认项；标出缺失状态。
  3. 让设计师/开发核对；Bot 不直接改设计文件。
  4. 用目标市场的拼写/日期/货币；全文一致。
  5. 长句拆短；不确定的表达标出来让母语者审。

验收标准

  • 只读边界明确
  • 组件和状态有清单
  • 文案有来源
  • 设计文件未被修改
  • 拼写/日期/货币一致，母语者可读

边界与限制

  • Figma API 权限和文件结构影响提取
  • 视觉细节要人看
  • 不能替代设计评审
  • 非母语审校可能漏掉语气问题

常见问题

能自动改设计稿吗？

不建议；先做只读交接。

能提取图片吗？

可以导出资源；版权要确认。

能保持品牌语气吗？

提供 2–3 个英文样例最有效。
