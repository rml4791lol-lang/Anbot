Anbot · 把 Figma 接进设计交接｜2–3 人小队版

设计交接不是发个链接；要把组件、状态、文案和边界写清。 人少时最怕职责重叠；每个 Bot 和每个人都要有唯一交付。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先只读一个文件，提取组件和文案，再生成交接清单，改动由设计师确认。 在2–3 人小队下，先先按交付分角色，不按聊天窗口分角色，再按验收表逐项确认。

适合谁

  • 设计和开发交接的团队
  • 要从 Figma 提取文案的人
  • 需要减少设计走查的人
  • 两三个人分工协作的小队

怎么做

  1. 接一个 Figma 文件，只读页面、组件和文本。
  2. 生成组件清单、状态、文案和待确认项；标出缺失状态。
  3. 让设计师/开发核对；Bot 不直接改设计文件。
  4. 写清谁做 Main Bot、谁做专业 Bot，以及每个交付由谁最终确认。
  5. 群聊只放共享上下文；私聊和草稿不要全量同步，避免噪声。

验收标准

  • 只读边界明确
  • 组件和状态有清单
  • 文案有来源
  • 设计文件未被修改
  • 每个交付只有一个最终负责人

边界与限制

  • Figma API 权限和文件结构影响提取
  • 视觉细节要人看
  • 不能替代设计评审
  • 人手少，跨领域复核仍然要外部支持

常见问题

能自动改设计稿吗？

不建议；先做只读交接。

能提取图片吗？

可以导出资源；版权要确认。

两个人怎么分 Bot？

一个人管 Main Bot 和验收，另一个人管专业 Bot 和领域判断。
