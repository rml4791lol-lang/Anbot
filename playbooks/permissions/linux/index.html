Anbot · 给 Bot 团队设权限边界｜Linux版

多 Agent 的第一风险是权限扩散；先设边界，再谈自动化。 Linux 多用于构建和服务；先准备依赖，再谈桌面能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先按角色列必要权限，再默认关闭高风险工具，最后设审批和审计。 在Linux下，先先确认 Node/依赖、权限和是否需要图形界面，再按验收表逐项确认。

适合谁

  • 要上线 Bot 团队的管理者
  • 处理敏感数据的组织
  • 需要给审计解释权限的人
  • 在 Linux 服务器/桌面运行的团队

怎么做

  1. 列角色、任务、需要的工具和数据范围。
  2. 按最小权限分配；高风险工具只给特定 Bot。
  3. 设审批点和审计记录；定期复核权限。
  4. 从源码构建，记录版本和依赖；不要混用系统 Node。
  5. 无图形界面的环境只跑能无头执行的任务，桌面能力另行确认。

验收标准

  • 每个 Bot 权限可解释
  • 高风险工具默认关闭
  • 审批记录可查
  • 有定期复核机制
  • 构建可复现，任务在目标环境跑通

边界与限制

  • 权限模型因组织而异
  • 共享账号会破坏审计
  • 不能替代身份系统
  • 官方没有 Linux 安装包，桌面能力不保证

常见问题

能让所有 Bot 共用管理员账号吗？

不建议；无法区分责任。

能临时提权吗？

可以，但要有时限和审批。

有 Linux 安装包吗？

当前发布页没有；需要从源码构建。
