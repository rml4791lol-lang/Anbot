Anbot · 给 Bot 团队设权限边界｜macOS版

多 Agent 的第一风险是权限扩散；先设边界，再谈自动化。 macOS 上先确认文件和权限；不要假设云端一定有副本。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先按角色列必要权限，再默认关闭高风险工具，最后设审批和审计。 在macOS下，先先确认工作区路径、磁盘权限和 Apple 芯片/Intel 包，再按验收表逐项确认。

适合谁

  • 要上线 Bot 团队的管理者
  • 处理敏感数据的组织
  • 需要给审计解释权限的人
  • 在 Mac 上运行的团队

怎么做

  1. 列角色、任务、需要的工具和数据范围。
  2. 按最小权限分配；高风险工具只给特定 Bot。
  3. 设审批点和审计记录；定期复核权限。
  4. 安装包按芯片选；首次运行按发布页说明放行。
  5. 文件操作只用本地路径；导出前检查换行和编码。

验收标准

  • 每个 Bot 权限可解释
  • 高风险工具默认关闭
  • 审批记录可查
  • 有定期复核机制
  • 安装包与芯片匹配，任务能在本机复跑

边界与限制

  • 权限模型因组织而异
  • 共享账号会破坏审计
  • 不能替代身份系统
  • 部分 Windows 专属工具/Office 能力可能不同

常见问题

能让所有 Bot 共用管理员账号吗？

不建议；无法区分责任。

能临时提权吗？

可以，但要有时限和审批。

Apple 芯片和 Intel 用同一个包吗？

不；发布页有 arm64 和 x64 两个包。
