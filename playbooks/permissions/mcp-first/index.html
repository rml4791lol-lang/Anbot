Anbot · 给 Bot 团队设权限边界｜MCP 优先版

多 Agent 的第一风险是权限扩散；先设边界，再谈自动化。 MCP 优先时先接只读工具，按 Bot 分配权限，高风险工具默认关闭。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先按角色列必要权限，再默认关闭高风险工具，最后设审批和审计。 在MCP 优先下，先先接一个只读 MCP，列出工具清单，再按验收表逐项确认。

适合谁

  • 要上线 Bot 团队的管理者
  • 处理敏感数据的组织
  • 需要给审计解释权限的人
  • 用 MCP 接内部工具的团队

怎么做

  1. 列角色、任务、需要的工具和数据范围。
  2. 按最小权限分配；高风险工具只给特定 Bot。
  3. 设审批点和审计记录；定期复核权限。
  4. 工具按需加载，不要全部 Always。
  5. 运行时探针确认实际加载和权限。

验收标准

  • 每个 Bot 权限可解释
  • 高风险工具默认关闭
  • 审批记录可查
  • 有定期复核机制
  • 工具清单可见，权限按 Bot 分配，高风险默认关闭

边界与限制

  • 权限模型因组织而异
  • 共享账号会破坏审计
  • 不能替代身份系统
  • MCP 服务器质量和限流由提供方决定

常见问题

能让所有 Bot 共用管理员账号吗？

不建议；无法区分责任。

能临时提权吗？

可以，但要有时限和审批。

能接本地 MCP 吗？

可以，通过本地网关；具体端口看文档。
