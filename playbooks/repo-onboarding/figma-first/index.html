Anbot · 给新成员生成仓库导览｜Figma 优先版

新人最需要的不是架构长文，而是「先跑什么、看哪几个文件、怎么确认没跑错」。 Figma 优先时设计文件只读，改动先复制分支。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先让 Bot 找入口脚本和最小可运行路径，再生成导览和验证命令，最后由老成员校对。 在Figma 优先下，先先只读一个文件，提取组件/文案/状态，再按验收表逐项确认。

适合谁

  • 要带新人的维护者
  • 刚加入项目的开发
  • 需要把隐性知识写下来的人
  • 以 Figma 为设计真源的团队

怎么做

  1. 扫描 README、包管理文件、CI 和最近提交，找真正的入口。
  2. 生成「环境准备—最小运行—看哪几个文件—常见失败」四段导览。
  3. 让新成员按导览跑一遍，把卡点补回文档；不要假设老成员的口头说明。
  4. 设计稿不直接改；需要改时先复制分支。
  5. 交接清单标出缺失状态和待确认文案。

验收标准

  • 导览能在一个干净环境跑通
  • 每个命令有预期输出
  • 关键文件有用途说明
  • 卡点有明确求助路径
  • 设计文件未被修改，交接清单可核对

边界与限制

  • 不能替代真正的架构评审
  • 私有环境可能需要额外凭据
  • 仓库很大时要限定范围
  • 视觉细节和版权需要人判断

常见问题

能自动改 README 吗？

可以生成草稿；提交前让维护者复核。

需要跑全量测试吗？

先跑最小路径，再按改动范围补测试。

能自动改设计稿吗？

不建议；先做只读交接。
