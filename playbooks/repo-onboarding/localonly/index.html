Anbot · 给新成员生成仓库导览｜纯本地数据版

新人最需要的不是架构长文，而是「先跑什么、看哪几个文件、怎么确认没跑错」。 纯本地场景先确认模型和工具都不外传，再谈能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先让 Bot 找入口脚本和最小可运行路径，再生成导览和验证命令，最后由老成员校对。 在纯本地数据下，先先列数据流，关掉会外传内容的连接器，再按验收表逐项确认。

适合谁

  • 要带新人的维护者
  • 刚加入项目的开发
  • 需要把隐性知识写下来的人
  • 数据不能出本机的团队

怎么做

  1. 扫描 README、包管理文件、CI 和最近提交，找真正的入口。
  2. 生成「环境准备—最小运行—看哪几个文件—常见失败」四段导览。
  3. 让新成员按导览跑一遍，把卡点补回文档；不要假设老成员的口头说明。
  4. 模型、检索、日志都留在本机；逐项确认没有外部请求。
  5. 敏感文件先脱敏；本地模型能力不足时明确降级范围。

验收标准

  • 导览能在一个干净环境跑通
  • 每个命令有预期输出
  • 关键文件有用途说明
  • 卡点有明确求助路径
  • 数据流图显示没有外部传输，日志本地保存

边界与限制

  • 不能替代真正的架构评审
  • 私有环境可能需要额外凭据
  • 仓库很大时要限定范围
  • 本地模型能力和更新速度有限

常见问题

能自动改 README 吗？

可以生成草稿；提交前让维护者复核。

需要跑全量测试吗？

先跑最小路径，再按改动范围补测试。

能完全离线吗？

取决于模型和工具；先确认哪些步骤需要联网。
