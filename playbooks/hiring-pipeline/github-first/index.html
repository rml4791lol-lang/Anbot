Anbot · 整理招聘 pipeline｜GitHub 优先版

招聘 pipeline 要跟进度，不是把简历堆在表格里。 GitHub 优先时先只读接入，写操作走草稿和审批。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先统一阶段定义，再按时效和下一步整理，最后标出停滞和需要反馈的人。 在GitHub 优先下，先先接一个仓库只读，再让 Bot 写 Issue/PR 草稿，再按验收表逐项确认。

适合谁

  • 招聘 HR
  • 用人经理
  • 要优化招聘流程的团队
  • 以 GitHub 为任务/代码真源的团队

怎么做

  1. 统一阶段、来源、岗位和下一步定义。
  2. 按停留时间找停滞；每个候选人写下一步和负责人。
  3. 生成周报；隐藏敏感个人信息，只保留招聘所需字段。
  4. Issue/PR 状态以 GitHub 为准；其他表只做视图。
  5. 合并、发布、改权限保留人工审批。

验收标准

  • 阶段定义统一
  • 停滞有下一步
  • 候选人隐私最小化
  • 没有歧视性字段
  • 没有双写，草稿能回到具体 Issue/PR

边界与限制

  • ATS 数据质量决定结果
  • 招聘决策由人做
  • 各地隐私法规不同
  • API 限流和私有仓库权限要单独处理

常见问题

能自动发拒信吗？

可以生成草稿；发送前人工确认。

能评分候选人吗？

不建议自动排序；只整理证据。

能自动合并吗？

不建议；合并和发布保留人工确认。
