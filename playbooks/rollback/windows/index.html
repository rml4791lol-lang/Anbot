Anbot · 为一次改动准备回滚｜Windows版

回滚不是失败后的补救；要在改动前就写好。 Windows 上先测路径、换行和 Office 兼容，再放量。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先记录基线和变更，再写回滚步骤，最后在非生产环境验证一次。 在Windows下，先先确认安装包、路径分隔符和 Office 版本，再按验收表逐项确认。

适合谁

  • 要发布变更的团队
  • 让 Bot 改文件/配置的人
  • 需要值班手册的人
  • 在 Windows 上运行的团队

怎么做

  1. 记录当前版本、配置、数据和依赖基线。
  2. 写回滚命令/步骤和影响范围；标出不可逆操作。
  3. 在测试环境演练回滚，确认能恢复到基线。
  4. 用 Windows 安装包；路径尽量用绝对路径并加引号。
  5. 批量脚本先在样本目录跑；确认编码和换行一致。

验收标准

  • 基线可复现
  • 回滚步骤可执行
  • 不可逆操作有标记
  • 演练结果有记录
  • 路径/编码/Office 兼容通过样本测试

边界与限制

  • 数据回滚可能丢失新数据
  • 生产权限不能随意给 Bot
  • 外部服务状态难回滚
  • 不同 Windows 版本的权限和字体有差异

常见问题

能自动回滚吗？

可以执行脚本，但高风险操作要人审批。

回滚后要做什么？

验证核心功能并记录事故原因。

Windows 10 能用吗？

发布页写明 Windows 10/11 64 位；以实际安装结果为准。
