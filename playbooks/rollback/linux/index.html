Anbot · 为一次改动准备回滚｜Linux版

回滚不是失败后的补救；要在改动前就写好。 Linux 多用于构建和服务；先准备依赖，再谈桌面能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先记录基线和变更，再写回滚步骤，最后在非生产环境验证一次。 在Linux下，先先确认 Node/依赖、权限和是否需要图形界面，再按验收表逐项确认。

适合谁

  • 要发布变更的团队
  • 让 Bot 改文件/配置的人
  • 需要值班手册的人
  • 在 Linux 服务器/桌面运行的团队

怎么做

  1. 记录当前版本、配置、数据和依赖基线。
  2. 写回滚命令/步骤和影响范围；标出不可逆操作。
  3. 在测试环境演练回滚，确认能恢复到基线。
  4. 从源码构建，记录版本和依赖；不要混用系统 Node。
  5. 无图形界面的环境只跑能无头执行的任务，桌面能力另行确认。

验收标准

  • 基线可复现
  • 回滚步骤可执行
  • 不可逆操作有标记
  • 演练结果有记录
  • 构建可复现，任务在目标环境跑通

边界与限制

  • 数据回滚可能丢失新数据
  • 生产权限不能随意给 Bot
  • 外部服务状态难回滚
  • 官方没有 Linux 安装包，桌面能力不保证

常见问题

能自动回滚吗？

可以执行脚本，但高风险操作要人审批。

回滚后要做什么？

验证核心功能并记录事故原因。

有 Linux 安装包吗？

当前发布页没有；需要从源码构建。
