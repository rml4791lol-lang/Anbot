Anbot · 把收件箱清成任务清单｜Linux版

任务清单最常见的病是「什么都重要」；先分清影响和可执行性。 Linux 多用于构建和服务；先准备依赖，再谈桌面能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先收集所有输入，再按影响/紧急/可执行/依赖四格分类，最后只留下周行动。 在Linux下，先先确认 Node/依赖、权限和是否需要图形界面，再按验收表逐项确认。

适合谁

  • 被消息淹没的人
  • 要管多项目的人
  • 团队任务入口混乱的组织
  • 在 Linux 服务器/桌面运行的团队

怎么做

  1. 收集消息、邮件、Issue 和会议待办，去重。
  2. 按四格分类；不能行动的归档，缺信息的写追问。
  3. 生成本周任务和 defer 清单；每项有下一步和日期。
  4. 从源码构建，记录版本和依赖；不要混用系统 Node。
  5. 无图形界面的环境只跑能无头执行的任务，桌面能力另行确认。

验收标准

  • 每项有下一步
  • 不能行动的没有硬留
  • 依赖有owner
  • 本周清单不超过容量
  • 构建可复现，任务在目标环境跑通

边界与限制

  • 输入可能不完整
  • 优先级需要人判断
  • 不能替代项目管理
  • 官方没有 Linux 安装包，桌面能力不保证

常见问题

能自动排优先级吗？

可以按规则建议；最终由人定。

能接多个工具吗？

可以，但先统一任务入口。

有 Linux 安装包吗？

当前发布页没有；需要从源码构建。
