Anbot · 把收件箱清成任务清单｜GitHub 优先版

任务清单最常见的病是「什么都重要」；先分清影响和可执行性。 GitHub 优先时先只读接入，写操作走草稿和审批。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先收集所有输入，再按影响/紧急/可执行/依赖四格分类，最后只留下周行动。 在GitHub 优先下，先先接一个仓库只读，再让 Bot 写 Issue/PR 草稿，再按验收表逐项确认。

适合谁

  • 被消息淹没的人
  • 要管多项目的人
  • 团队任务入口混乱的组织
  • 以 GitHub 为任务/代码真源的团队

怎么做

  1. 收集消息、邮件、Issue 和会议待办，去重。
  2. 按四格分类；不能行动的归档，缺信息的写追问。
  3. 生成本周任务和 defer 清单；每项有下一步和日期。
  4. Issue/PR 状态以 GitHub 为准；其他表只做视图。
  5. 合并、发布、改权限保留人工审批。

验收标准

  • 每项有下一步
  • 不能行动的没有硬留
  • 依赖有owner
  • 本周清单不超过容量
  • 没有双写，草稿能回到具体 Issue/PR

边界与限制

  • 输入可能不完整
  • 优先级需要人判断
  • 不能替代项目管理
  • API 限流和私有仓库权限要单独处理

常见问题

能自动排优先级吗？

可以按规则建议；最终由人定。

能接多个工具吗？

可以，但先统一任务入口。

能自动合并吗？

不建议；合并和发布保留人工确认。
