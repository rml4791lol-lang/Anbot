Anbot · 决定要不要给 Anbot 写插件｜2–3 人小队版

不是所有需求都值得写插件；先看现有连接器和 MCP 能不能解决。 人少时最怕职责重叠；每个 Bot 和每个人都要有唯一交付。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先列需求/权限/界面，再判断配置/MCP/插件，最后做最小原型。 在2–3 人小队下，先先按交付分角色，不按聊天窗口分角色，再按验收表逐项确认。

适合谁

  • 要扩展 Anbot 的开发者
  • 有内部系统的团队
  • 想定制界面的组织
  • 两三个人分工协作的小队

怎么做

  1. 写清需求、用户、权限和必须出现的界面。
  2. 先试配置/MCP；只有运行时/界面必须改时才写插件。
  3. 做最小原型并测升级兼容；不要直接改核心代码。
  4. 写清谁做 Main Bot、谁做专业 Bot，以及每个交付由谁最终确认。
  5. 群聊只放共享上下文；私聊和草稿不要全量同步，避免噪声。

验收标准

  • 需求不能由现有能力满足
  • 插件边界清楚
  • 升级路径可维护
  • 权限最小化
  • 每个交付只有一个最终负责人

边界与限制

  • 插件会增加维护成本
  • 升级可能破坏兼容
  • 不是所有界面都可扩展
  • 人手少，跨领域复核仍然要外部支持

常见问题

插件和 MCP 怎么选？

先 MCP；需要改运行时/界面再插件。

能改核心吗？

不建议；按扩展接口做。

两个人怎么分 Bot？

一个人管 Main Bot 和验收，另一个人管专业 Bot 和领域判断。
