Anbot · 决定要不要给 Anbot 写插件｜运营/行政版

不是所有需求都值得写插件；先看现有连接器和 MCP 能不能解决。 运营任务要固定输入模板和输出目录，减少口头变体。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先列需求/权限/界面，再判断配置/MCP/插件，最后做最小原型。 在运营/行政下，先先固定输入模板、命名和归档目录，再按验收表逐项确认。

适合谁

  • 要扩展 Anbot 的开发者
  • 有内部系统的团队
  • 想定制界面的组织
  • 运营、行政、财务等流程岗位

怎么做

  1. 写清需求、用户、权限和必须出现的界面。
  2. 先试配置/MCP；只有运行时/界面必须改时才写插件。
  3. 做最小原型并测升级兼容；不要直接改核心代码。
  4. 每类任务做一个模板；字段不齐的先补，不要靠猜。
  5. 输出按日期/项目归档；每周抽查一次重复和漏项。

验收标准

  • 需求不能由现有能力满足
  • 插件边界清楚
  • 升级路径可维护
  • 权限最小化
  • 同类任务输出结构一致，能批量复核

边界与限制

  • 插件会增加维护成本
  • 升级可能破坏兼容
  • 不是所有界面都可扩展
  • 例外流程多，模板不可能覆盖全部

常见问题

插件和 MCP 怎么选？

先 MCP；需要改运行时/界面再插件。

能改核心吗？

不建议；按扩展接口做。

能处理临时需求吗？

可以，但先标为例外，不要污染标准模板。
