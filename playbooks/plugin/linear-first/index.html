Anbot · 决定要不要给 Anbot 写插件｜Linear 优先版

不是所有需求都值得写插件；先看现有连接器和 MCP 能不能解决。 Linear 优先时状态只写一处；Bot 只做草稿/评论。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先列需求/权限/界面，再判断配置/MCP/插件，最后做最小原型。 在Linear 优先下，先先接一个项目只读，再生成分诊/验收草稿，再按验收表逐项确认。

适合谁

  • 要扩展 Anbot 的开发者
  • 有内部系统的团队
  • 想定制界面的组织
  • 以 Linear 为任务真源的团队

怎么做

  1. 写清需求、用户、权限和必须出现的界面。
  2. 先试配置/MCP；只有运行时/界面必须改时才写插件。
  3. 做最小原型并测升级兼容；不要直接改核心代码。
  4. Issue 状态以 Linear 为准；外部表只读。
  5. 状态变更走审批；冲突回 Linear 处理。

验收标准

  • 需求不能由现有能力满足
  • 插件边界清楚
  • 升级路径可维护
  • 权限最小化
  • 没有双写，状态变更可追溯

边界与限制

  • 插件会增加维护成本
  • 升级可能破坏兼容
  • 不是所有界面都可扩展
  • 工作流状态因团队而异，不能硬编码

常见问题

插件和 MCP 怎么选？

先 MCP；需要改运行时/界面再插件。

能改核心吗？

不建议；按扩展接口做。

能自动关闭 Issue 吗？

先写关闭建议，由人确认。
