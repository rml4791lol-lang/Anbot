Anbot · 做一次竞品功能对比｜Linear 优先版

竞品对比最怕拿厂商宣传当事实；先定维度，再找可验证证据。 Linear 优先时状态只写一处；Bot 只做草稿/评论。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定 5–7 个对比维度，再收集官方文档/价格/截图，最后标出未验证项。 在Linear 优先下，先先接一个项目只读，再生成分诊/验收草稿，再按验收表逐项确认。

适合谁

  • 要做选型的人
  • 写竞品分析的内容团队
  • 需要给老板汇报的人
  • 以 Linear 为任务真源的团队

怎么做

  1. 确定对比对象、维度、地区和版本日期。
  2. 每个维度找官方来源或实测截图，记录链接和日期。
  3. 生成对比表和差异结论；无法验证的写「未验证」，不要猜。
  4. Issue 状态以 Linear 为准；外部表只读。
  5. 状态变更走审批；冲突回 Linear 处理。

验收标准

  • 每个结论有来源和日期
  • 对比维度一致
  • 价格/版本写清
  • 未验证项明确标出
  • 没有双写，状态变更可追溯

边界与限制

  • 厂商功能迭代快
  • 部分地区/套餐差异大
  • 不能替代真实试用
  • 工作流状态因团队而异，不能硬编码

常见问题

能保证信息最新吗？

不能；会标日期，发布前再核对。

能做功能打分吗？

可以，但分数要对应证据和权重。

能自动关闭 Issue 吗？

先写关闭建议，由人确认。
