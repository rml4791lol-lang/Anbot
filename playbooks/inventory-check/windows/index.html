Anbot · 核对库存账实差异｜Windows版

库存差异不能只看总数；要定位到 SKU、批次和出入库记录。 Windows 上先测路径、换行和 Office 兼容，再放量。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先对齐 SKU 和时间点，再做账实对比，最后按原因分类并保留调整依据。 在Windows下，先先确认安装包、路径分隔符和 Office 版本，再按验收表逐项确认。

适合谁

  • 仓库/运营人员
  • 要做盘点报告的人
  • 被账实差异困扰的团队
  • 在 Windows 上运行的团队

怎么做

  1. 统一 SKU、批次、单位和盘点时间点。
  2. 对比系统数与实盘数，标出差异数量和金额影响。
  3. 按漏记/错记/损耗/未入库分类；调整建议由人确认。
  4. 用 Windows 安装包；路径尽量用绝对路径并加引号。
  5. 批量脚本先在样本目录跑；确认编码和换行一致。

验收标准

  • SKU 和时间点对齐
  • 差异能追到单据
  • 原因分类有证据
  • 调整不覆盖原始记录
  • 路径/编码/Office 兼容通过样本测试

边界与限制

  • 盘点数据准确性决定结果
  • 多仓库要分开算
  • 不能替代财务盘点制度
  • 不同 Windows 版本的权限和字体有差异

常见问题

能自动调整库存吗？

不建议；先出差异清单和依据。

能处理多单位吗？

可以，但要先统一换算规则。

Windows 10 能用吗？

发布页写明 Windows 10/11 64 位；以实际安装结果为准。
