Anbot · 核对库存账实差异｜GitHub 优先版

库存差异不能只看总数；要定位到 SKU、批次和出入库记录。 GitHub 优先时先只读接入，写操作走草稿和审批。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先对齐 SKU 和时间点，再做账实对比，最后按原因分类并保留调整依据。 在GitHub 优先下，先先接一个仓库只读，再让 Bot 写 Issue/PR 草稿，再按验收表逐项确认。

适合谁

  • 仓库/运营人员
  • 要做盘点报告的人
  • 被账实差异困扰的团队
  • 以 GitHub 为任务/代码真源的团队

怎么做

  1. 统一 SKU、批次、单位和盘点时间点。
  2. 对比系统数与实盘数，标出差异数量和金额影响。
  3. 按漏记/错记/损耗/未入库分类；调整建议由人确认。
  4. Issue/PR 状态以 GitHub 为准；其他表只做视图。
  5. 合并、发布、改权限保留人工审批。

验收标准

  • SKU 和时间点对齐
  • 差异能追到单据
  • 原因分类有证据
  • 调整不覆盖原始记录
  • 没有双写，草稿能回到具体 Issue/PR

边界与限制

  • 盘点数据准确性决定结果
  • 多仓库要分开算
  • 不能替代财务盘点制度
  • API 限流和私有仓库权限要单独处理

常见问题

能自动调整库存吗？

不建议；先出差异清单和依据。

能处理多单位吗？

可以，但要先统一换算规则。

能自动合并吗？

不建议；合并和发布保留人工确认。
