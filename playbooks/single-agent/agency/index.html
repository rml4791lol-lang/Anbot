Anbot · 什么时候用单 Agent 更合适｜代运营/客户交付版

单 Agent 不是落后；简单任务用它更快、更便宜。 客户交付最怕串数据和串口径；先隔离客户，再复用模板。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先看任务是否需要多角色/交接；不需要就用单 Agent，需要再升级。 在代运营/客户交付下，先按客户建独立工作区和验收清单，再按验收表逐项确认。

适合谁

  • 被多 Agent 方案绕晕的人
  • 做一次性任务的人
  • 要控制成本的团队
  • 服务多个客户的代理/外包团队

怎么做

  1. 判断任务是否一次性、单文件、无需多人验收。
  2. 用单 Agent 跑一遍，记录返工和交接成本。
  3. 只有出现明确角色/并行/交接需求时才升级团队。
  4. 每个客户单独目录、单独凭据、单独知识库，不共用上下文。
  5. 交付前用同一套验收复核；客户确认前不发布。

验收标准

  • 任务真的不需要多角色
  • 成本更低
  • 返工可接受
  • 升级路径清楚
  • 客户数据不跨项目混用，交付有客户确认记录

边界与限制

  • 单 Agent 上下文有限
  • 复杂任务容易漏项
  • 不能替代团队协作
  • 多客户并行会增加上下文和权限复杂度

常见问题

单 Agent 能接工具吗？

可以；工具接入不等于多 Agent。

什么时候升级？

出现独立子任务和交接需求时。

能复用同一个 Bot 吗？

可以复用能力模板，但客户数据和凭据必须隔离。
