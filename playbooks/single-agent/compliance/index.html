Anbot · 什么时候用单 Agent 更合适｜合规/审计版

单 Agent 不是落后；简单任务用它更快、更便宜。 合规场景先定留存和审批，再谈自动化；没有记录的结果不算可审计。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先看任务是否需要多角色/交接；不需要就用单 Agent，需要再升级。 在合规/审计下，先先定记录字段、留存期限和审批点，再按验收表逐项确认。

适合谁

  • 被多 Agent 方案绕晕的人
  • 做一次性任务的人
  • 要控制成本的团队
  • 需要留痕和审计的团队

怎么做

  1. 判断任务是否一次性、单文件、无需多人验收。
  2. 用单 Agent 跑一遍，记录返工和交接成本。
  3. 只有出现明确角色/并行/交接需求时才升级团队。
  4. 输入、计划、工具、审批、产物、失败原因都留痕。
  5. 敏感字段脱敏；日志归档到只读位置。

验收标准

  • 任务真的不需要多角色
  • 成本更低
  • 返工可接受
  • 升级路径清楚
  • 任务能端到端还原，审批和产物有记录

边界与限制

  • 单 Agent 上下文有限
  • 复杂任务容易漏项
  • 不能替代团队协作
  • 合规解释需法务/合规确认，不能只看模板

常见问题

单 Agent 能接工具吗？

可以；工具接入不等于多 Agent。

什么时候升级？

出现独立子任务和交接需求时。

能只留结果吗？

不够；关键决策和审批也要留。
