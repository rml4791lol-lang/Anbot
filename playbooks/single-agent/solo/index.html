Anbot · 什么时候用单 Agent 更合适｜一人公司版

单 Agent 不是落后；简单任务用它更快、更便宜。 你既是老板也是执行者，最缺的是可复跑和可验收，而不是更多 Bot。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先看任务是否需要多角色/交接；不需要就用单 Agent，需要再升级。 在一人公司下，先先把 Bot 压到 1–2 个，选一条能独立验收的链路，再按验收表逐项确认。

适合谁

  • 被多 Agent 方案绕晕的人
  • 做一次性任务的人
  • 要控制成本的团队
  • 一个人负责从输入到交付的从业者

怎么做

  1. 判断任务是否一次性、单文件、无需多人验收。
  2. 用单 Agent 跑一遍，记录返工和交接成本。
  3. 只有出现明确角色/并行/交接需求时才升级团队。
  4. 把输入、输出目录和验收清单写在同一个文件里，避免靠记忆。
  5. 每次只改一个变量；失败时回到上一个检查点，不要同时调模型和流程。

验收标准

  • 任务真的不需要多角色
  • 成本更低
  • 返工可接受
  • 升级路径清楚
  • 一个人能在 30 分钟内复跑并解释结果

边界与限制

  • 单 Agent 上下文有限
  • 复杂任务容易漏项
  • 不能替代团队协作
  • 没有第二个人交叉复核，事实性结论要额外抽检

常见问题

单 Agent 能接工具吗？

可以；工具接入不等于多 Agent。

什么时候升级？

出现独立子任务和交接需求时。

一个人需要几个 Bot？

先 1 个 Main Bot + 1 个专业 Bot，跑通再加；不要用 Bot 数量掩盖流程问题。
