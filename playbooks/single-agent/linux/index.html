Anbot · 什么时候用单 Agent 更合适｜Linux版

单 Agent 不是落后；简单任务用它更快、更便宜。 Linux 多用于构建和服务；先准备依赖，再谈桌面能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先看任务是否需要多角色/交接；不需要就用单 Agent，需要再升级。 在Linux下，先先确认 Node/依赖、权限和是否需要图形界面，再按验收表逐项确认。

适合谁

  • 被多 Agent 方案绕晕的人
  • 做一次性任务的人
  • 要控制成本的团队
  • 在 Linux 服务器/桌面运行的团队

怎么做

  1. 判断任务是否一次性、单文件、无需多人验收。
  2. 用单 Agent 跑一遍，记录返工和交接成本。
  3. 只有出现明确角色/并行/交接需求时才升级团队。
  4. 从源码构建，记录版本和依赖；不要混用系统 Node。
  5. 无图形界面的环境只跑能无头执行的任务，桌面能力另行确认。

验收标准

  • 任务真的不需要多角色
  • 成本更低
  • 返工可接受
  • 升级路径清楚
  • 构建可复现，任务在目标环境跑通

边界与限制

  • 单 Agent 上下文有限
  • 复杂任务容易漏项
  • 不能替代团队协作
  • 官方没有 Linux 安装包，桌面能力不保证

常见问题

单 Agent 能接工具吗？

可以；工具接入不等于多 Agent。

什么时候升级？

出现独立子任务和交接需求时。

有 Linux 安装包吗？

当前发布页没有；需要从源码构建。
