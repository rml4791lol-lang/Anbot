Anbot · 把本地 CLI Agent 接进团队｜纯本地数据版

本地 CLI 不需要被替代；让它保留自己的运行时，只把结果接进团队。 纯本地场景先确认模型和工具都不外传，再谈能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先让 CLI 独立跑通，再作为专业 Bot 接入群聊，交接用文件和任务，不复制登录。 在纯本地数据下，先先列数据流，关掉会外传内容的连接器，再按验收表逐项确认。

适合谁

  • 已经用 Claude Code/Codex 的人
  • 想保留本地工具链的开发者
  • 要多 Agent 协作的团队
  • 数据不能出本机的团队

怎么做

  1. 先单独跑通 CLI 的登录、模型和工具，记录限制。
  2. 把它作为专业 Bot 接入，只接收任务和共享文件。
  3. 交接用文件/任务板，不把 CLI 的凭据复制到 Anbot。
  4. 模型、检索、日志都留在本机；逐项确认没有外部请求。
  5. 敏感文件先脱敏；本地模型能力不足时明确降级范围。

验收标准

  • CLI 保留自己的登录和套餐
  • 任务交接有文件
  • 没有复制凭据
  • 失败能回到 CLI 自己处理
  • 数据流图显示没有外部传输，日志本地保存

边界与限制

  • CLI 的能力和计费由提供方决定
  • 上下文不共享
  • 并发和限流要单独测
  • 本地模型能力和更新速度有限

常见问题

能共用模型额度吗？

不能假设；各运行时分别计费。

能同时跑多个 CLI 吗？

可以，但注意本机资源和限流。

能完全离线吗？

取决于模型和工具；先确认哪些步骤需要联网。
