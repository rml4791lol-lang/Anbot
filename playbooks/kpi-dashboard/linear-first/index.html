Anbot · 搭一个 KPI 看板｜Linear 优先版

看板不是图表越多越好；每个指标都要能驱动一个动作。 Linear 优先时状态只写一处；Bot 只做草稿/评论。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先选 5–7 个能驱动动作的指标，再定义口径和阈值，最后做趋势与异常。 在Linear 优先下，先先接一个项目只读，再生成分诊/验收草稿，再按验收表逐项确认。

适合谁

  • 要给团队做看板的人
  • 每周开数据会的人
  • 需要统一指标口径的人
  • 以 Linear 为任务真源的团队

怎么做

  1. 列出业务目标、使用场景和每个指标对应的动作。
  2. 定义口径、数据源、更新频率和阈值；删掉不驱动动作的图表。
  3. 生成看板草稿和异常说明；用历史数据回测阈值是否合理。
  4. Issue 状态以 Linear 为准；外部表只读。
  5. 状态变更走审批；冲突回 Linear 处理。

验收标准

  • 每个指标有口径和负责人
  • 图表能回答一个问题
  • 阈值有依据
  • 异常能追到数据源
  • 没有双写，状态变更可追溯

边界与限制

  • 不能替代业务判断
  • 数据延迟会影响决策
  • 看板维护需要owner
  • 工作流状态因团队而异，不能硬编码

常见问题

能做实时看板吗？

取决于数据源刷新能力；先确认延迟。

能自动发周报吗？

可以生成摘要草稿；发送前人工确认。

能自动关闭 Issue 吗？

先写关闭建议，由人确认。
