Anbot · 把 Notion 接成团队知识入口｜GitHub 优先版

Notion 接不好会变成第二个垃圾场；先定单一真相源和写入规则。 GitHub 优先时先只读接入，写操作走草稿和审批。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先选一个数据库做只读试点，再让 Bot 写草稿页，发布由人确认。 在GitHub 优先下，先先接一个仓库只读，再让 Bot 写 Issue/PR 草稿，再按验收表逐项确认。

适合谁

  • 用 Notion 管项目的团队
  • 要把会议/任务写进 Notion 的人
  • 需要统一知识入口的组织
  • 以 GitHub 为任务/代码真源的团队

怎么做

  1. 选一个数据库/页面，明确字段和只读范围。
  2. 让 Bot 生成页面草稿或数据库条目，保留来源链接。
  3. 设发布/归档审批；不要让 Bot 直接改权限或删页面。
  4. Issue/PR 状态以 GitHub 为准；其他表只做视图。
  5. 合并、发布、改权限保留人工审批。

验收标准

  • 读写范围明确
  • 草稿有来源
  • 没有重复数据库
  • 发布由人确认
  • 没有双写，草稿能回到具体 Issue/PR

边界与限制

  • Notion API 权限和速率有限制
  • 页面结构变化会破坏映射
  • 富文本格式可能丢失
  • API 限流和私有仓库权限要单独处理

常见问题

能自动整理整个 workspace 吗？

建议先从一个数据库开始，不要全量动。

能同步回 Notion 吗？

可以写草稿；覆盖原页面要审批。

能自动合并吗？

不建议；合并和发布保留人工确认。
