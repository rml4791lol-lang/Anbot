Anbot · 把 PR 拆成审查清单｜云模型版

PR 很大时，审查者会漏掉发布风险；先把 PR 拆成可逐项确认的清单。 云模型先分开「文件在哪」和「内容发给谁」，敏感数据先脱敏。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先按行为变化、兼容性、测试、发布四组拆清单，再让 Bot 为每组找证据。 在云模型下，先先确认服务商条款、数据保留和可脱敏字段，再按验收表逐项确认。

适合谁

  • 要审大 PR 的维护者
  • 需要给团队定审查口径的人
  • 经常漏发布检查的开发
  • 使用云模型服务商的团队

怎么做

  1. 读 PR 描述、diff、测试和发布配置，列出受影响面。
  2. 按四组生成检查项：行为、兼容性、测试、发布/回滚。
  3. 每项标「已证实/待确认/不适用」，不要把未看过的项打勾。
  4. 只发必要字段；能本地预处理就不要整文件上传。
  5. 记录模型服务商、区域和保留政策；敏感任务保留人工复核。

验收标准

  • 四个维度都有结论
  • 高风险项有人负责
  • 不适用项有理由
  • 审查记录能附到 PR
  • 发送字段最小化，服务商和保留政策有记录

边界与限制

  • 不能替代领域专家判断
  • UI/性能问题需要实际运行
  • 发布配置因项目而异
  • 服务商条款和价格会变，跨境传输要单独确认

常见问题

能直接批准 PR 吗？

不建议；Anbot 生成审查记录，批准由人做。

能只看 diff 吗？

不够；还要看调用方、测试和发布配置。

云模型会保存数据吗？

看服务商条款；不要把不确定当成不会保存。
