Anbot · 把 Issue 分诊成可执行任务｜Android 远程版

Issue 列表不等于任务列表；分诊要给出影响范围、复现状态和下一步。 Android 是远程入口；实际执行在电脑端，先确认配对和在线。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先让 Bot 读 Issue 和仓库上下文，按影响/复现/优先级分组，再人工定负责人。 在Android 远程下，先先确认电脑端在线、配对成功和网络可达，再按验收表逐项确认。

适合谁

  • 每周要清 Issue 的维护者
  • 被重复 Issue 淹没的小团队
  • 需要把用户反馈转成开发任务的人
  • 用手机远程控制电脑端团队的人

怎么做

  1. 拉取 Issue 标题、正文、标签和关联 PR；先不写评论。
  2. 按「可复现/缺信息/重复/需要设计」四类归档，每条给依据。
  3. 生成分诊草稿和缺失信息清单；负责人和优先级由人确认。
  4. 手机只做发起/查看；文件落到电脑端工作区。
  5. 不要把完整运行时和大批文件搬到手机；断网先暂停任务。

验收标准

  • 每个 Issue 有分诊结论和依据
  • 缺信息的 Issue 有具体追问清单
  • 重复 Issue 指向原始链接
  • 没有自动替人排优先级
  • 手机能发起并看到结果，执行仍在电脑端

边界与限制

  • 不能替代产品优先级判断
  • 标签体系不统一会误分
  • 自动评论要先审
  • 电脑端离线时 Android 不能独立跑完整团队

常见问题

能自动关闭 Issue 吗？

不建议；可以先写关闭建议，由人确认。

能读私有仓库吗？

取决于你给的连接器权限；先按最小权限接入。

Android 能单独跑 Bot 吗？

它主要通过加密连接控制电脑端团队，不是完整运行时。
