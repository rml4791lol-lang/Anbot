Anbot · 扫描一个细分市场｜GitHub 优先版

市场扫描不是罗列公司；要回答市场多大、谁在买、钱从哪里来。 GitHub 优先时先只读接入，写操作走草稿和审批。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定义市场边界，再收集规模/玩家/渠道证据，最后把估算和事实分开。 在GitHub 优先下，先先接一个仓库只读，再让 Bot 写 Issue/PR 草稿，再按验收表逐项确认。

适合谁

  • 要做市场进入分析的人
  • 写行业报告的人
  • 评估新业务的管理者
  • 以 GitHub 为任务/代码真源的团队

怎么做

  1. 定义产品、客户、地区和年份边界。
  2. 收集规模、增长率、主要玩家、渠道和监管来源。
  3. 生成事实表与估算表；每个估算写假设和误差范围。
  4. Issue/PR 状态以 GitHub 为准；其他表只做视图。
  5. 合并、发布、改权限保留人工审批。

验收标准

  • 市场边界清楚
  • 事实和估算分开
  • 来源有日期
  • 主要玩家没有遗漏关键类型
  • 没有双写，草稿能回到具体 Issue/PR

边界与限制

  • 公开数据口径不一
  • 估算依赖假设
  • 不能替代尽调
  • API 限流和私有仓库权限要单独处理

常见问题

能给出市场规模吗？

可以给区间和假设，不假装精确。

能覆盖全球吗？

可以，但建议按地区分开。

能自动合并吗？

不建议；合并和发布保留人工确认。
