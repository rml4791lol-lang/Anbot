Anbot · 做供应商年度复盘｜Linux版

供应商复盘要看履约证据，不要只看关系好坏。 Linux 多用于构建和服务；先准备依赖，再谈桌面能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先定评分维度和权重，再收集履约证据，最后给续约/观察/退出建议。 在Linux下，先先确认 Node/依赖、权限和是否需要图形界面，再按验收表逐项确认。

适合谁

  • 管理供应商的人
  • 要续约谈判的采购
  • 需要给管理层报告的人
  • 在 Linux 服务器/桌面运行的团队

怎么做

  1. 定交付、质量、响应、成本、合规五维度和权重。
  2. 收集合同、SLA、工单、发票和事故记录作为证据。
  3. 评分并写续约建议；没有证据的维度标「数据不足」。
  4. 从源码构建，记录版本和依赖；不要混用系统 Node。
  5. 无图形界面的环境只跑能无头执行的任务，桌面能力另行确认。

验收标准

  • 每个分数有证据
  • 权重合理
  • 风险和退出成本写清
  • 建议不是拍脑袋
  • 构建可复现，任务在目标环境跑通

边界与限制

  • 内部数据可能不全
  • 关系因素难量化
  • 不能替代合同谈判
  • 官方没有 Linux 安装包，桌面能力不保证

常见问题

能自动打分吗？

可以按规则算，但要人确认权重。

能比较新供应商吗？

可以，用同一套维度。

有 Linux 安装包吗？

当前发布页没有；需要从源码构建。
