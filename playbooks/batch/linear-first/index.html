Anbot · 批量处理一批文件｜Linear 优先版

批量任务不要一把梭；先做小样本，再分批跑。 Linear 优先时状态只写一处；Bot 只做草稿/评论。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先列清单和样本，再分批执行、记录失败，最后汇总结果和重试。 在Linear 优先下，先先接一个项目只读，再生成分诊/验收草稿，再按验收表逐项确认。

适合谁

  • 要处理几百个文件的人
  • 做数据/内容批处理的人
  • 需要稳定产出的人
  • 以 Linear 为任务真源的团队

怎么做

  1. 生成文件清单，按类型/大小/优先级分组。
  2. 先跑 3–5 个样本，确认输出格式和失败模式。
  3. 分批执行并记录成功/失败；失败项单独重试。
  4. Issue 状态以 Linear 为准；外部表只读。
  5. 状态变更走审批；冲突回 Linear 处理。

验收标准

  • 清单完整可复跑
  • 样本通过再放量
  • 失败项有原因
  • 结果目录结构统一
  • 没有双写，状态变更可追溯

边界与限制

  • API/模型限流会影响速度
  • 大文件占资源
  • 部分失败不能静默跳过
  • 工作流状态因团队而异，不能硬编码

常见问题

能一次跑 3000 个吗？

建议分批；先测吞吐和失败率。

失败了会重跑全部吗？

只重跑失败清单。

能自动关闭 Issue 吗？

先写关闭建议，由人确认。
