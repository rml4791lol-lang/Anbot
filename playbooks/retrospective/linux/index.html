Anbot · 主持一次迭代复盘｜Linux版

复盘要安全、具体、可行动；先定规则，再谈问题。 Linux 多用于构建和服务；先准备依赖，再谈桌面能力。

本页是 3,000 个场景页中的 1 个，基于 Anbot 0.0.1；下面给出 5 个步骤、5 条验收标准、4 个限制。

一句话答案：先收集事实和数据，再按「继续/停止/开始」生成行动项，最后定负责人和验证点。 在Linux下，先先确认 Node/依赖、权限和是否需要图形界面，再按验收表逐项确认。

适合谁

  • 要主持复盘的人
  • 迭代总踩同样坑的团队
  • 远程团队
  • 在 Linux 服务器/桌面运行的团队

怎么做

  1. 提前收集迭代数据、事件和匿名反馈。
  2. 按「继续/停止/开始」讨论，每个行动项写负责人和验证方式。
  3. 把行动项放进下个迭代；没有owner的项不算完成。
  4. 从源码构建，记录版本和依赖；不要混用系统 Node。
  5. 无图形界面的环境只跑能无头执行的任务，桌面能力另行确认。

验收标准

  • 讨论基于事实
  • 行动项可验证
  • 有负责人和日期
  • 没有指名羞辱个人
  • 构建可复现，任务在目标环境跑通

边界与限制

  • 匿名反馈可能失真
  • 不能替代管理决策
  • 跨团队问题需要升级
  • 官方没有 Linux 安装包，桌面能力不保证

常见问题

能自动生成复盘报告吗？

可以生成草稿；敏感讨论要人工处理。

能匿名收集吗？

可以，但要说明可见范围。

有 Linux 安装包吗？

当前发布页没有；需要从源码构建。
