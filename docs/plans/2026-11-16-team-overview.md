# 团队总览

- 日期：2026-11-16
- 相关：Bot 视图的全窗口团队、项目与 Agent 工作区

## 为什么

对话适合处理一个 Bot 的事，但要回答“整个团队现在在做什么、哪里等我、最近变了什么、项目沉淀了什么、Agent 是否在按要求工作”，必须逐个打开会话。侧栏已经保存了分组、状态和未读；团队总览把这些现有状态、项目工作目录、记忆和规范证据汇成一个工作区，不另建任务系统、运行时或视觉 token。

## 已定的行为

- Bot 视图右侧有一个窄的「团队总览」页签，沿用现有右侧面板的入口方式。
- 点开后打开当前工作区上的大画布，不切走对话；关闭按钮、遮罩和 Escape 都能关闭。桌面端保留四周留白，手机端占满视口。
- 点 Bot 或群聊会关闭总览并打开对应会话。
- Agent 模式不显示页签。手机宽度下总览占满视口，页签仍可打开。
- 「团队」只读 `roster.bots`、`roster.rooms`、`roster.sections`、`work.bots`、`work.rooms`、`work.waiting`、`work.approvals`、`roster.questions`、`useSessionStatus` 和 `roster.learning`。
- 「项目」把现有 sidebar section 当作项目边界，不新增项目表；项目里的 Bot、群聊、工作目录、Goal、记忆和规范都从现有记录投影。空 section 也保留，用户可以在总览里通过现有 `section-save` 新建项目。
- 项目进度不是一个伪造的百分比，而是「计划 / 记录检查 / 证据覆盖」三层完成模型：有 Goal 时显示阶段节点和通过数；有 `.ds-bot/quality.json` 时显示 passed/expected 和逐项检查矩阵；没有 Goal 时明确显示“未设计划”，但仍可从已记录检查判断“检查已验证 / 检查需要处理”。
- 项目展开后有两种非进度条可视化：知识矩阵按决策、规范、来源、技能、检查、已验证结果计数；经验时间线用最小化的 dot + 时间 + 动作呈现，默认不展开正文，点击后才显示原因、证据和来源。
- 时间线纳入 Goal 事件、任务更新、阶段通过或退回、记忆、规范/说明更新、来源复核、检查记录和最近工作，因此项目与任务都能从结果回看到动作、原因和证据。
- 项目改动使用追加式审计记录，不从聊天或完成度反推。Bot 在真实文件改动或项目检查点后用 `record_project_change` 写入“谁、何时、做了什么、为什么、涉及文件、实际证据、改前 / 改后”，记录不可通过界面编辑。
- 记录账本保存在 DS Bot 自己的数据目录，不写进用户项目，避免记录行为本身污染 Git 工作树；Git 仓库同时读取最近提交和当前未提交文件，作为可复核的自动事实来源。
- 项目运行时会自动观察 Bot 工作结束后的文件变化并补记“观察到的变更”。自动记录只说明文件和来源，不替 Bot 编造原因、进展或测试结果；Bot 自己记录的内容明确标为“Bot 上报”，Git 内容明确标为“来自 Git”。
- 需要更完整的叙述时，使用可见的项目记录员 Bot 接收完成事实并调用同一记录工具；不使用隐藏子 Agent 维护审计链，避免记录脱离团队可见性、审批和会话历史。
- 项目工作项沿用 Orca 的分层方式：任务源上下文、Issue / PR 分栏、预设范围（全部 / 我的 / 待我评审）、稳定缓存键和软刷新彼此分开。GitHub 工作项只读取，不把列表 UI 变成第二套权限系统。
- 项目从 Git remote 自动识别 GitHub 仓库；优先用已登录的 `gh`，不可用时回退到 DS Bot 的 GitHub connector token。读取失败保留上一份可用数据并标为过期，不显示空列表冒充“没有工作”。
- GitHub 的打开、合并、关闭、检查状态、评审结论和指派变化按稳定快照做差异，写入项目变更时间线；首次读取只建立基线，不把所有既有 Issue / PR 倒灌成“刚打开”。
- `team-overview-insights` 只读每个 Bot/群聊的 memory view，并扫描项目 `workDir` 中的 `AGENTS.override.md`、`AGENTS.md` 或 `CLAUDE.md`。它统计规则行、官方链接和 `package.json` 的 test/lint/typecheck/check/build 脚本；不执行脚本，也不编造通过率。
- 项目可以记录 `.ds-bot/quality.json`：`{ checkedAt, expected, passed, total, checks: [{ name, status }] }`。总览显示实际记录；没有文件时明确显示“还没有记录检查结果”。
- 项目可以用 `.ds-bot/standards.json` 声明自己的标准包。示例：

```json
{
  "profile": "miniprogram",
  "name": "微信小程序项目规范",
  "sources": [
    { "name": "小程序设计指南", "url": "https://developers.weixin.qq.com/miniprogram/design/", "scope": ["UI", "navigation"], "version": "2026-11", "checkedAt": "2026-11-16" }
  ],
  "requiredFiles": ["project.config.json", "app.json", "app.wxss"],
  "requiredChecks": ["lint", "privacy"]
}
```

- 项目可以用 `.ds-bot/integrations.json` 配置任务源；不写时从 Git remote 自动识别。示例：

```json
{
  "github": {
    "enabled": true,
    "repo": "owner/repository",
    "state": "open",
    "limit": 40,
    "refreshSeconds": 60
  }
}
```

- `state` 支持 `open`、`closed`、`merged` 和 `all`；刷新间隔限制在 20–600 秒，避免把 GitHub API 变成高频轮询。手动“刷新”绕过缓存，普通 15 秒总览轮询只复用缓存。

- 没有声明文件时按真实文件识别项目类型：`miniprogram`（`project.config.json`、`app.json` 等）、`video`（`STORYBOARD.md`、`SCRIPT.md`、`hyperframes.json` 或视频工程文件）、`web`、`app`、`backend`；都不匹配时为 `generic`。
- 每个项目的“标准档案”列出采用的文件及作用：`AGENTS.md`（项目规则）、`README.md` / `CONTRIBUTING.md`（项目说明）、`package.json`（命令）、`.ds-bot/standards.json`（标准包）、`.ds-bot/quality.json`（检查结果）、项目标记文件和声明但缺失的必需文件。
- 经验沉淀同时汇总规则文件标题、项目说明标题、记忆主题和已批准学习；每条都保留来源文件或来源层，方便人核对，不只显示数量。
- 完成模型会把标准包声明的 `requiredFiles` 和 `requiredChecks` 纳入判断：必需文件缺失或必需检查没有记录时显示“规范未完整”，不会把其他检查通过误当成整体达标。
- 项目页下方有“标准库”，按小程序、视频、Web、App、后端等类型汇总项目数、采用文件、官方来源、规则和技能；这是跨项目复用标准的入口，不复制文件内容。
- 摘要左侧是一个状态环：按 Bot/群聊的首要状态切分，中心是团队条目总数；右侧显示进行中、需要你、等待队友、未读。颜色只用现有工作绿、强调色、等待黄和弱化灰。
- 「需要你」显示审批和问题卡，带已等待时间和进入对应 Bot 的入口。
- 「正在发生」显示现有 work 中的 Bot 与群聊工作、工具动作、对象或说明，以及持续时间。
- 「Bot 和群聊」沿用侧栏分组，显示角色、空闲/执行中/等你处理/有未读和消息预览；分组头有最多 10 个状态点，快速看出该组是否在运行、等你或只是空闲。
- 「最近记录」按每个 Bot 和群聊自己的 `lastAt` 与 `preview` 排序。
- 「学习」只显示已经存在于 `roster.learning` 的待批准提案。
- 「Agent」显示每个 Bot 以及单独的 DSH Agent：实时运行状态、待处理/已批准/已拒绝的学习、记忆使用情况、项目规范文件、来源链接和可用检查。规范证据固定为文件夹、规则、来源、检查四项，不把“找到证据”说成“测试通过”。
- 记忆库把所有 Bot/群聊的记忆主题和最近条目聚合起来；点击条目沿用现有记忆面板，并保留隐私和权限边界。
- 「发布」把正式站、预览、本机入口和文档站收在一个持久目录里。记录保存在 DS Bot 自己的 `<home>/sites.json`，包含名称、URL、环境、分组、项目目录、仓库、标签、备注、收藏和归档状态；不写进用户项目。
- 发布目录支持建组、改组、删组和站点归组；删除分组只解除归属，不删除站点。每个站点可编辑、收藏、软归档、恢复和手动检查；新建后自动检查一次。
- 健康检查只发 `HEAD`，遇到 `405` / `501` 回退到 `GET`，区分在线、需要登录、HTTP 错误、离线和未检查，并记录状态码、延迟与检查时间。结果只在用户检查或新建后更新，不把一次检查写成长期可用性承诺。
- 发布页按分组、收藏和异常优先排序，支持环境筛选、按名称 / URL / 标签 / 备注搜索、归档开关和无匹配结果时的清除筛选入口。页面只记录和打开入口，不执行部署、重启或杀进程。
- 全部头像、房间簇、状态动效、主题、字号、按钮、滚动和弹簧动画沿用现有组件。

## 中间状态

- roster 未就绪：显示与最终布局同形的骨架。
- 启动失败且 roster 未到：显示错误态和关闭入口，不编造旧团队。
- 空团队：说明 Bot、群聊和交接出现后会显示在这里。
- 运行中：`thinking`、`searching`、`working`、`sending` 和换会话沿用 `toolState` / `botState`。
- 等你处理：审批和问题卡优先于其他活动。
- 等待队友：从 `work.waiting` 读出等待的 Bot 或群聊并写出名字。
- 未读：从 `useSessionStatus` 读取完成未读和待交互。
- 没有消息预览时不补文案，显示空预览。
- 面板打开后焦点进入关闭按钮，Tab 只能在面板内循环；方向键切换团队、项目、Agent、发布四个视图；Escape、关闭按钮和遮罩关闭后，焦点回到右侧页签；点条目进入会话时不抢回焦点，打开记忆时也不抢回焦点。
- 项目/Agent 证据初次加载时显示读取态；刷新失败保留上一份可用数据并提示错误。打开项目/Agent 页后每 15 秒轻量重读，手动刷新绕过 2 秒缓存；页面明确显示“自动 · 15s”。
- 自动更新直接观察 `state.revision`、Goal、work/session 状态、Bot/群聊 `lastAt`、memory view、`AGENTS.md` mtime/规则/链接、`package.json` 脚本和 `.ds-bot/quality.json`，不生成后台任务，也不执行项目脚本。
- 项目记录初次读取显示已有 Git 提交、未提交文件或账本记录；没有变更时明确显示“还没有记录项目变更”。自动采集失败不影响总览读取，项目页仍显示上一次可用记录。
- 发布页初次读取显示读取态；空目录说明可以添加第一个入口；有记录但筛选无结果时显示“没有匹配”并提供清除筛选；只有归档记录时提供“显示已归档”。读取失败保留上一份可用数据并显示错误条。
- 站点检查中禁用对应操作；保存、归档、恢复和分组变更失败时把宿主的错误显示出来，不用内存结果伪装成功。移动端把站点主体、状态和操作排成三层，动作不丢失。

## 不做什么

- 不新建任务、Goal 或队列存储；任务账本和派活关系仍是唯一来源。
- 不在总览里直接批准或回答；跳到现有卡片，写入仍只走权限和审批路径。
- 不做拖拽进度，不执行任意项目脚本，不把没有记录过的检查显示成通过。
- 不让自动观察冒充 Bot 的说明，不允许隐藏子 Agent 单独维护项目历史，也不把 Git 提交数量当成项目完成度。
- 不在总览里直接合并 PR、重跑检查或修改 Issue。这里展示事实并链接回 GitHub；写操作仍由有权限的 Bot 经过现有权限、审批和审计路径完成。
- 发布页本阶段不自动扫描本机端口、不按工作区猜测归属、不启动或停止服务，也不执行部署。它只管理已经被用户记录的入口并做可达性检查。
- 不新建主题、图标或头像体系。

## 已知限制

- 本机端口自动发现、工作区归属置信度、页面标题探测和“固定到发布目录”留到下一阶段；当前本机入口需要手动填写 URL。
- 健康检查只代表检查当时的 HTTP 响应，不保存长期 uptime、截图或部署版本历史，也不绕过登录页。
