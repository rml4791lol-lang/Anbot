# Anbot architecture

Anbot runs as the local desktop app or as the `ds-bot` plugin inside DeepSeek Harness. [App profile](../app/src/profile.mjs) assembles the pinned Cordis bundles. [Plugin entry](../ds-bot/index.js) mounts the product on DSH's Sessions, tools and model routes. Anbot owns the Bot roster, Goals, handoffs and project evidence. The corresponding decisions are indexed in [ARCHITECTURE_DECISIONS.md](../ARCHITECTURE_DECISIONS.md).

Three rings guide the implementation: a protected kernel with five contracts, two meta engines that consume them, and optional extensions. The [implementation plan](superpowers/plans/2026-11-24-ds-bot-harness.md) records which phases have passed and how. The Phase 0 compatibility boundary covers desktop identity, local paths and distribution only.

[Legacy desktop identity](../app/src/legacy.mjs) retains an existing Electron shell directory and its encryption identity. [Default locations](../app/src/place.mjs) preserve existing locations and give fresh installations their own directories. DSH and the plugin retain their package and protocol identifiers.

The desktop [overlay composer](../app/src/profile-overlay.mjs) matches the effective Cordis row by ID and module identity. It merges nested mappings and replaces arrays and Cordis expressions as units. Rows containing protected keys or opaque environment and header maps stay in the original profile and are omitted from generated overlays. Onboarding, search, Office and Goal overlays all use this composer. Provider rows remain under DSH configuration. The [pinned-runtime overlay tests](../app/test/app-patch.test.mjs) verify that unrelated values survive and stale generated files are removed.

The desktop [search overlay](../app/src/search-patch.mjs) restores the bundled search selector when the automatic provider is disabled. The selector is applied to the effective web row so profile-specific fetch options survive.

The [shell approval rule](../ds-bot/src/host/shell-approval.js) runs in the native DSH tool pipeline before a Bot's Bash or PowerShell command is dispatched. It requests one-time approval for recognized recursive removals, destructive Git operations, pushes, disk commands and privilege elevation. Earlier denials and cancellations still apply. DSH owns the approval audit and the sandbox used for execution. The rule recognizes common command forms and relies on the sandbox for enforcement of filesystem boundaries.

The Bot's [evidence workflow](../ds-bot/src/host/bot-workflow.js) runs a fixed review in the Workflow engine available to its current DSH Session. Anbot passes only counts-ready facts from recent recorded tool results and retains the native run handle until DSH settles and disposes it. The [X-Ray tab](../ds-bot/src/client/bot-xray.js) shows that result and offers cancellation. Its latest run view is local to the current host process.

The [task spec](../ds-bot/src/host/bot-spec.js) is saved on the Bot through the existing roster writer. Writes require the current private Session and the revision the editor loaded. The [prompt assembler](../ds-bot/src/host/prompt.js) reads the saved scope and checklist for that private Session. A new private Session uses the same spec until the user changes or clears it.

The [Session capabilities view](../ds-bot/src/host/bot-runtime-view.js) reads the live Agent’s model selection and separates it from the last recorded request route. It shows modules from the activated DSH preset, permissions from DSH’s sandbox policy and extension evidence for the exact Session. A Skill is available when it is in the scoped catalog, its body can load and DSH admits the loader and the Skill itself. An incomplete catalog leaves an absent Skill unverified. The MCP view separates an initial connection from current transport health. Local Agent installation and sign-in come from executable and authentication probes. CLI Skills and permissions are managed by the CLI.

The [context view](../ds-bot/src/host/bot-context-view.js) exposes a [typed projection](../ds-bot/src/host/bot-context-view.d.ts) of the current native DSH Session at a captured event sequence. It returns retained message IDs in model-visible order and follows explicit event citations through chained replacements to report exact source ranges. Positional replacement endpoints are recorded separately because the interval may contain unrelated log events. The projection contains no message bodies and leaves the original event log intact. Token pressure and the advertised model window are separate observations. X-Ray shows pressure against the usable window and the thresholds used by [context stewardship](../ds-bot/src/host/parts.js). The usable window reserves room for output, and pressure can include a heuristic delta from the latest provider sample.

The [restart recovery path](../ds-bot/src/host/resume.js) reserves one automatic continuation for an interrupted turn in the existing in-flight journal before dispatch. A further interruption parks that work. A held worktree also parks recovery. X-Ray exposes the pause and lets the user resume the private Session explicitly once it is available.

An [explicit model retry](../ds-bot/src/host/model-retry.js) applies to the latest failed private DSH turn. It records the prior and chosen routes in a Session plugin record, uses native selection for one turn, and restores the prior choice before more queued work starts or when reattaching after a crash. A later explicit selection or change to the Bot's configured route takes precedence.

The [worktree probe](../ds-bot/src/host/bot-worktree.js) reads linked-worktree identity from Git. It reports Session readiness only when a live DSH Agent is attached to the same Git metadata directory. A running Agent reports its own current `turn/start` sequence until a matching `turn/end` closes it. Ownership and quiescence have separate checks.

The [ACP driver](../ds-bot/src/host/local-agents/acp.js) keeps the original prompt RPC open when DSH stops reading its stream. The adapter tracks that request until a terminal ACP reply confirms the prompt ended. A transport failure or an invalid reply leaves the stop unconfirmed, including when the live bridge closes.

The [Codex driver](../ds-bot/src/host/local-agents/codex.js) records the native turn ID from the start reply. When cancellation arrives early, the driver sends the interrupt as soon as the ID is known. The adapter waits for a terminal notification with the same thread and turn IDs. A reply to the interrupt request alone leaves the stop unconfirmed.

The [Claude Code driver](../ds-bot/src/host/local-agents/claude.js) sends at most one interrupt per active prompt and waits for a terminal `result` from that CLI Session. Prompts are serialized because stream-json results identify the Session. An interrupt acknowledgement, a mismatched result or an early process exit leaves the stop unconfirmed.

The [worktree hold](../ds-bot/src/host/worktree-hold.js) records local ownership in the Bot roster. A Session first enters `stopping` to prevent new prompts and steps. Native DSH Agents must reach idle before the hold can advance to `held`. ACP, Codex and Claude Code Agents also require terminal evidence from the adapter. The host rechecks the attached worktree before granting the hold. Return requires a confirmed hold for the same Session ID, canonical root and Git metadata directory. The Agent must be idle, with no inbox items, delegated work, active Workflow or unsettled local prompt.

[Checkpoint capture](../ds-bot/src/host/bot-checkpoint.js) pairs the flushed DSH Session sequence and memory journal cursor with a local Git ref. A scratch index captures working copies of paths tracked at HEAD and keeps the user's staged index intact. A task-bound turn carries its task and attempt IDs, which the [capture service](../ds-bot/src/host/worktree-hold.js) checks against the Goal or handoff before saving. When a handoff finishes, its active record is retired and the existing task ledger keeps the closing Session and attempt IDs for later checkpoints. Ordinary private turns can be checkpointed without a task. The Bot roster keeps the ordered records. Capture requires a held worktree and a stopped Agent. Untracked files and staged content that differs from the working copy are outside the snapshot.

[Checkpoint restore](../ds-bot/src/host/worktree-hold.js) reserves a child Session ID in the roster before creating its linked worktree. Both [read-only and writable restores](../ds-bot/src/host/checkpoint-session.js) seed a native Session at the saved sequence and verify the applicable sandbox policy before publishing the Agent. One roster write publishes the Session and worktree together and clears the reservation. On restart, Anbot checks a reserved child's DSH header before archiving it. If the Session was never created, Anbot checks the live registry and persistence before removing the matching clean Git worktree. It retains the reservation when identity, activity or working files prevent safe cleanup. If the memory journal has advanced, writable restore requires explicit consent to keep current memory.

The user can open the writable restore as a standalone DSH Session or switch the Bot’s private chat to it. Switching rechecks the held source and idle destination, then saves the active Session, private-chat worktree and transferred hold in one roster write. The source Session remains in the Bot’s history. The user returns the restored worktree before sending the next turn from the Bot chat.

New checkpoints record separate cursors for Bot and team memory. The [memory writer](../ds-bot/src/host/memory.js) uses journal append order to identify changes after each cursor. The checkpoint's review shows undoable entries attributed to its source Session. An explicit undo uses the existing journal writer and its exact-line conflict checks. User-authored changes and writes by other Sessions stay outside that undo list.
