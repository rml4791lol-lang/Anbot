# Anbot development and runbook

Use Node.js 24 for development and packages, as the [test workflow](../.github/workflows/test.yml) does. Run `npm run setup`, `npm test`, `npm run build`, `node scripts/build-client.mjs --check` and `npm run lint` in `ds-bot/`. Commit generated `ds-bot/client.js` when client sources change. Use the isolated bench described in [AGENTS.md](../AGENTS.md) for DSH host changes.

Desktop startup overlays restate only matching Cordis rows. To diagnose an omitted overlay, check the row’s effective module identity and the presence of protected credential and endpoint fields without printing their values. The original profile still owns that row.

When a native Bot issues a recognized high-risk Bash or PowerShell command, DSH requests one-time approval before dispatch. Rejecting cancels that tool call. An approved call still runs under the Session’s existing sandbox. CLI-backed Bots keep their execution engine’s own tool permission flow.

In **Create Bot → What this Bot does**, choose **Debugging** or **Code review** to fill the editable instructions and Skill shortlist. The options appear for native DSH Bots when their Skills are in the live catalog. Open **Skills** to review or edit the shortlist before creating the Bot.

Open **X-Ray → Session capabilities** to inspect the current Session. Expand **Skills and MCP** for scoped availability and **Loaded preset plugins** for the active DSH composition. A selected route appears separately when it differs from the last recorded request. For a local Agent, the panel reports the CLI installation and sign-in check.

Closing the desktop window keeps work running in the tray. Quitting while the Host reports a running Agent or native Workflow opens a confirmation. Escape keeps the Host running. If the Host cannot report activity, the confirmation says so.

An interrupted turn gets at most one automatic continuation after a restart. If X-Ray shows that recovery is paused, check the ongoing work, return the worktree if held, and choose **Resume interrupted work**. The continuation retains the prior task and attempt IDs when the original turn carried them.

On the latest private DSH failure card, choose **Retry with another model** and **Retry once** to use a selected model for that turn. The original route resumes on subsequent turns. Return a held worktree before retrying. This action appears when the host supports durable Session plugin records and serves another DSH model.

Run `node app/scripts/compare-search-repair.mjs prepare` from the repository root to reproduce the search-overlay regression in two detached worktrees in a temporary Git repository. The command uses the local npm cache and prints the comparison directory. Its `comparison.json` records the shared repair prompt, test digest and each arm’s instructions and Skill shortlist.

Use `node app/scripts/compare-search-repair.mjs bind <comparison-directory>` to check the worktree and sandbox bindings in a fresh pinned DSH host. It uses a closed loopback endpoint and sends no repair task. Use `node app/scripts/compare-search-repair.mjs run <comparison-directory>` with `ANBOT_REPAIR_BASE_URL`, `ANBOT_REPAIR_MODEL` and the credential expected by the adapter through `ANBOT_REPAIR_API_KEY`. The provider protocol defaults to `openai-responses` and can be set with `ANBOT_REPAIR_PROTOCOL`. Set `ANBOT_REPAIR_EFFORT` to a level the provider accepts on the wire. The driver declares and reads back that exact level before creating the Bots. Both Bots must reply from the configured route before receiving the repair task. The isolated host closes after the run. The run directory’s `bindings.json` records the observed worktree, Session, model route and tool names.

For the local DeepSeek Responses relay, set `ANBOT_REPAIR_BASE_URL=http://127.0.0.1:15721/v1`, `ANBOT_REPAIR_MODEL=deepseek-v4.1-flash` and `ANBOT_REPAIR_EFFORT=max`. Supply the adapter's bearer value in the launch environment. A local relay that authenticates upstream can accept a non-secret placeholder. Keep actual credentials out of the repository and evidence logs. Run `prepare` again to obtain clean worktrees for each new comparison.

Run `node app/scripts/compare-search-repair.mjs verify <comparison-directory>` to check both candidate diffs and rerun the identical acceptance tests. This also runs at the end of `run`. Use `node app/scripts/compare-search-repair.mjs takeover <DSH-run-directory>` with the same provider credential to reopen the successful run. Both Bots must refuse input during the hold and read a temporary human edit in their original Session after return. The driver records the evidence in `takeover.json`, removes its files and reruns the regression checks.

Run `npm ci`, `npm test` and `npm run build` in `app/`. Run `npm run pack` to build a local package and `npm run check-packed` to start and exercise that package in throwaway directories. The [release checklist](dev/release-checklist.md) covers platform verification. Start release notes from the [bilingual template](../.github/release-notes-template.md).

Open a Bot conversation's details and select **X-Ray** to run its recent evidence check. A profile needs the native Workflow engine in the Bot's Agent preset. The check can be cancelled while it runs. If the panel reports that the engine is missing, inspect the effective DSH preset for `workflow-ptc` and its dependencies. From `ds-bot/`, run `node --test test/bot-workflow.test.js` for the lifecycle and scope tests.

In **X-Ray**, save the task objective, constraints and checklist before sending the next instruction to the Bot. The current private Session reads the saved spec when DSH assembles its request. If another window saves first, reload the spec before editing it again. Clearing both fields removes the spec from subsequent requests.

For a Bot running on native DSH, ACP, Codex or Claude Code and attached to a linked Git worktree, open **X-Ray → Worktree control** and choose **Take over worktree**. Start editing after the panel confirms that you control the worktree. When the Session is idle and delegated work has settled, choose **Return worktree** and send the next instruction in the same conversation. The hold stays in effect across desktop restarts. While a local Agent’s stop is unconfirmed, the panel stays at **Waiting for the Bot to stop** and disables **Return worktree**. Retry checks the same local prompt in the same host. An interrupted local takeover retains its reservation if the previous host could not confirm the stop.

While holding a worktree, choose **Save checkpoint** to capture the conversation boundary and the working copies of tracked files. Expand **Checkpoint history** and choose **Create read-only preview** to materialize a separate linked worktree and native DSH conversation fork. **Open read-only preview** opens that Session. If the panel reports a memory change, review the current memory before using the preview to inform new work.

Choose **Restore to new worktree** to reopen a checkpoint for editing. If memory has changed since capture, select **Keep current memory when restoring** after reviewing the change. **Open restored Session** opens it as a standalone DSH conversation. To continue under the Bot’s identity, keep the original worktree held and choose **Switch Bot to restored Session**. This transfers the hold to the restored worktree and keeps the source Session in the Bot’s history. Choose **Return worktree** before resuming the Bot.

After an interrupted restore, Anbot checks the reserved child Session and Git worktree when the Host opens. It archives a verified unpublished child and removes its clean linked worktree. If the Host reports a mismatch or local edits, review the diagnostic and preserve the working files before retrying the restore.

In **Checkpoint history**, choose **Review memory changes** to see entries written by the source Session after capture. **Undo this change** reverses the selected entry through the memory journal. The undo is recorded in memory history. If the entry has since been edited, the writer reports a conflict when it cannot match the recorded line. Checkpoints created before per-scope cursors were available show that the review is unavailable.

The [release workflow](../.github/workflows/release.yml) targets the independent Anbot repository. Its private release assets require an authenticated browser or CLI for manual downloads. An installed app can use an explicitly configured update feed through `ANBOT_UPDATE_URL` or the legacy `DS_BOT_UPDATE_URL`. Keep credentials outside repository and package configuration.
