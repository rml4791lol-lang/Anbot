**一句话判据：改坏了，用户先看到画面坏 → 前端；先看到数据错、接口报 500 → 后端。**

按文件归谁：

| 前端 | 后端 |
|---|---|
| `pages/` `components/` `*.tsx` `*.vue` `*.css` | `routes/` `services/` `models/` `*.sql` |
| 交互、表单校验、图表配置 | 鉴权、队列、定时任务、部署脚本 |
| `public/` 图片字体动效 | `migrations/` 表结构 |

两边都能碰、但必须先问对方的是：`package.json`、构建配置、路由注册表。

**怎么合作：**
1. **契约先行**：接口要变，后端先写清「地址/入参/出参/错误码/谁跟着改」落盘，再动代码。前端只消费不改。
2. **交接物固定**：后端交前端 = 接口地址 + 一份真实响应样例 + 影响哪些页面；前端交后端 = 520/900 截图 + 交互验收记录 + 缺的字段清单。
3. **冲突按归属让 owner 改**，另一个提 diff，别两边一起动同一个文件。

**怎么变专业：**
- 每人一份手艺清单（常用库、惯用写法、自己踩过的坑），放自己记忆。
- 每周从经验流水里挑同类坑 ≥2 次的，写进自己指令。
- 换族互查：前端 `claude -p`、后端 `codex exec`，两个模型族互相挑刺，比自审可靠。
